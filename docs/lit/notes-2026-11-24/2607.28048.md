# 2607.28048: SKILL-KD: Contrastive Skill Distillation for LLM Agents

arXiv 2607.28048v4, 13 Oct 2026, cs.AI. 16 pages. Qiming Shi (1), Yibo Dou (3), Jiawen Zhu (2), Yulong Tao (4), Linbo Jin (4), Zhaolu Kang (3), Yunfan Zhou (1), Di Weng (2, corresponding). 1 State Key Lab of CAD&CG, Zhejiang University. 2 School of Software Technology, Zhejiang University. 3 School of Software and Microelectronics, Peking University. 4 Alibaba Group. No code link in the paper.

In one line: a stronger teacher writes a short text rule from the gap between its run and the weak student's failed run on the same task, and the rule is kept only if the student then passes that task. This is very close to Loopy's "tailored checked note" arm. Text is the only form tested.

## Claim (key numbers and where they are)

1. SKILL-KD lifts the macro-average over five benchmarks from 43.5 to 66.8 for a Qwen3.5-4B student with a Qwen3.7-plus teacher, and from 57.9 to 74.6 for a Qwen3.6-35B-A3B student with a ChatGPT-5.5 teacher. The best baseline, SkillOpt, gets 63.5 and 68.6 (Table 1).
2. The teacher-student contrast matters. Skills from the student's failure alone score 60.1, from the teacher's run alone 58.3, from one contrast with no re-run 59.0, full method 66.8 (Table 2).
3. The re-run check matters. Without it: 59.0. Without the teacher: 62.1. Without consolidation: 58.7 (Table 3).
4. Consolidation keeps the library small. 38 rules and 3,010 words with it, 85 rules without it (Tables 2, 4).
5. The teacher does not need to succeed. It solves 46.1% of the student-failed training tasks, and 39.2% of accepted patches come from runs where the teacher also failed (Table 5).

## Method, in enough detail to reproduce

Objects (§3.1). Student S, teacher T, consolidation agent C (the same model as the teacher). Skill library K is one Markdown file per benchmark. Each rule is (title, content, why, trace). Only title and content are shown to the student. Why and trace stay in an edit history H that only C sees. Evaluator r(x, trajectory) is in [0, 1].

Loop over training instances (§3.1, §3.2):
1. Student runs task x with the current library. If r = 1, skip to the next task.
2. If it fails, the teacher runs the same task with the same library.
3. C reads K, H, both trajectories and both scores and proposes patch p1.
4. The student re-runs the same task x with the patched library. If r = 1 the patch is committed to K.
5. If it still fails, C sees the new failed run and proposes a revised patch. Each revision is made against the original K and replaces the earlier one. Up to n = 3 rounds.
6. If no round passes, nothing is written. Failed patches are not stored in K or H.

Consolidation (§3.3, App. B). C is a multi-turn agent with two tools. `get_original_trajectories(edit_index)` pulls the full student and teacher runs behind an earlier edit. `submit_ops(ops)` commits at most three operations from add, update, delete; an empty list means skip. The prompt (App. B) sets the rule format: title of at most 8 words; content is one sentence "When <trigger>, do <action>"; the trigger must be type-level, not tied to file names, cell addresses, room names or object nouns; prefer update over add; delete overlapping rules. C also sees "the training evaluator record for each trajectory".

Runtime. The whole skill file for that benchmark goes in the prompt at training re-runs and at test. No retrieval. One library per benchmark (App. A).

Variants (§5.1, §5.2). Student-only: self-reflection on the failed run. Teacher-only: rules from the teacher run alone. Batch: four trajectories in one update. Pairwise, also called w/o Adaptive: one contrast, no re-run. w/o Teacher: the student's own failed run replaces the teacher run but re-runs stay. w/o Consolidation: no edit-history access.

Not stated: number of passes over the training set, instance order, temperature, which model each baseline used as its optimizer, whether baseline numbers were rerun or taken from the SkillOpt paper, and whether the evaluator record shown to C contains the gold answer.

## Setting, data, models

- Group 1: student Qwen3.5-4B, teacher and consolidator Qwen3.7-plus. Group 2: student Qwen3.6-35B-A3B, teacher and consolidator ChatGPT-5.5 (§4). All analysis after Table 1 is Group 1 only.
- Students served locally on four A100 80GB. Teachers through APIs. Medium reasoning effort for both (App. A).
- Benchmarks and train/validation/test sizes (Table 6): ALFWorld 39/18/134, SpreadsheetBench 80/40/280, SearchQA 400/200/1,400, LiveMath 35/18/124, DocVQA 107/53/374. Native splits where they exist, else 2:1:7 with seed 42, the SkillOpt protocol. SKILL-KD uses only the training split.
- SearchQA, DocVQA and LiveMath are single-round QA or multiple choice. SpreadsheetBench is multi-round code execution with openpyxl and pandas, at most 12 turns. ALFWorld allows 50 steps. So three of the five "agent benchmarks" are single-turn.
- Baselines: No Skill, EvoSkill, Trace2Skill, SkillGen, SkillOpt.
- "Each reported score was computed from a single complete evaluation run on the fixed test split" (App. A). No seeds, no intervals.

## Metrics (exact definitions)

- Test score: each benchmark's "native hard-success or exact-match" score on the test split, in percent. Avg is the unweighted mean of the five.
- Patch acceptance: a patch is accepted only if the student re-run on the same training task reaches r = 1.
- Cumulative training success at round i (§5.5, Table 7): share of training tasks whose student run has passed by round i. Round 0 is the first attempt.
- Table 5: teacher success = share of student-failed training tasks the teacher passes. "Accept | T success" and "Accept | T failure" = share of those tasks that end with an accepted patch. "Accepted from T failures" = share of accepted patches that came from teacher-failed runs.
- Library size: total rules and total words.

## Results, including weak and negative ones

Table 1, test scores (SearchQA, SpreadsheetBench, DocVQA, LiveMath, ALFWorld, Avg):
- Group 1 No Skill: 68.1, 9.3, 86.9, 22.4, 30.6, 43.5. SkillOpt: 71.2, 23.9, 89.0, 52.0, 81.3, 63.5. SKILL-KD: 79.2, 24.3, 89.3, 54.8, 86.6, 66.8.
- Group 2 No Skill: 72.7, 38.2, 87.6, 31.2, 59.7, 57.9. SkillOpt: 80.3, 47.5, 91.4, 41.6, 82.1, 68.6. SKILL-KD: 80.6, 49.3, 92.2, 54.8, 96.3, 74.6.
- I rechecked every Avg cell. They match.

How often a checked text patch fixes a failure. This is my arithmetic from Tables 5, 6 and 7, and the two tables agree with each other:
- Share of the weak student's failed training tasks fixed within three rounds: SearchQA 55% (54 of 99), SpreadsheetBench 16% (11 of 67), DocVQA 67% (12 of 18), LiveMath 35% (7 of 20), ALFWorld 44% (4 of 9). Pooled 41% (88 of 213). Mean of the five rates 43%.
- After one round only: SearchQA 40%, SpreadsheetBench 9%, DocVQA 61%, LiveMath 15%, ALFWorld 33%. Pooled about 30% (63 of 213). Mean of the five rates 32%.
- Loopy's tailored checked note (one round) fixed 27% on AppWorld. Same range as the one-round pooled figure here.
- These rates include any task that would have passed on a plain second try. The paper has no re-roll control, so they are upper bounds on what the patch itself did.
- The lowest rate, 16%, is on the one benchmark where the student must write and run code.

Weak and negative results:
- Several wins over SkillOpt are one to four test items: SpreadsheetBench 24.3 vs 23.9 (one item of 280), DocVQA 89.3 vs 89.0 (one of 374), Group 2 SearchQA 80.6 vs 80.3 (four of 1,400). Single run. The clear wins are Group 1 SearchQA (+8.0), ALFWorld (+5.3 and +14.2) and Group 2 LiveMath (+13.2).
- Baseline text skills sometimes land below No Skill. Group 1: EvoSkill DocVQA 79.7 vs 86.9, SkillGen LiveMath 21.0 vs 22.4. Group 2: EvoSkill SpreadsheetBench 32.9 vs 38.2, Trace2Skill SpreadsheetBench 33.2 vs 38.2, Trace2Skill LiveMath 29.6 vs 31.2. The authors do not comment. SKILL-KD itself is never below No Skill.
- EvoSkill and Trace2Skill raise SpreadsheetBench for the weaker student (+8.6, +10.0) and lower it for the stronger one (-5.3, -5.0).
- Every method gains less on the stronger student. Average gain in points, Group 1 then Group 2: EvoSkill 8.0 and 4.0, Trace2Skill 10.1 and 2.0, SkillGen 9.0 and 3.1, SkillOpt 20.0 and 10.7, SKILL-KD 23.3 and 16.7 (my arithmetic from Table 1). As a share of the room left to 100, SKILL-KD closes 41% and 40%, so no real difference for it.
- LiveMath: when the teacher succeeded, no patch was ever accepted (0.0%, but that is 2 tasks). All 7 accepted LiveMath patches came from runs where the teacher also failed. The teacher solved only 10% of the student's LiveMath failures (Table 5).
- ALFWorld: no patch accepted when the teacher failed (2 tasks).
- SpreadsheetBench: 2.4% acceptance when the teacher failed (1 of 42).
- Round 2 adds as much as round 1 on LiveMath (8.6 vs 8.5 points, 3 tasks each), so "the first round is dominant" does not hold there (Table 7).
- Without consolidation, SpreadsheetBench drops to 14.6 and LiveMath to 27.4 (Table 3).
- SKILL-KD scores exactly 54.8 on LiveMath for both students. Possible on 124 items (68 correct) but worth a second look.

## Limitations

Theirs: needs benchmarks with explicit success metrics; needs teacher-student contrasts that differ in a useful way; and third, text skills work best for "procedural guidance that the frozen student can follow through prompting, and may need to be combined with retrieval, tool learning, or model adaptation". That third point names the gap Loopy tests and does not test it.

Mine:
- Single evaluation run per cell. On LiveMath (124 items) one standard error is about 4.5 points.
- Student strength and teacher change together between the two groups. Nothing about student strength can be separated from the teacher.
- No re-roll control. The re-run is on the same task with a nondeterministic student at medium reasoning effort. Some "fixed" tasks would pass on a plain second try with no patch. The paper never re-runs the student with no patch or with an unrelated patch.
- No placebo or generic rule control.
- The check is on the same instance the patch was written from, and C sees the evaluator record. If that record holds the gold answer, a patch can pass by carrying the answer. The LiveMath rules look like this: rules 001, 003 and 004 are single-item facts (a PDE blow-up criterion, r-variation of circular averages with r = 2, block-stable graph criticality), against the paper's own "type-level trigger" rule.
- LiveMath rule 002 is a test-taking shortcut: when an option says a stronger result exists, pick it. KV-Skill (2608.05475) calls LiveMath a "threshold task" driven by one such procedure. The LiveMath jump is probably this shortcut, not math skill. That is my reading.
- The SearchQA rules are Jeopardy formatting conventions. This sits badly with the claim that skills are "reusable procedural guidance rather than benchmark-specific prompt tuning" (§4.1).
- The method only looks at tasks the student fails. It never checks whether a new rule breaks a task the student already passed. Drift is discussed with three anecdotes (§5.4), not counted.
- The No Skill and SkillOpt cells here equal the values the KV-Skill paper (2608.05475) reports or attributes to the SkillOpt paper (No Skill LiveMath 22.4; SkillOpt 52.0, 71.2, 89.0, 23.9, 81.3 on the 4B model). They may be copied from SkillOpt, not rerun. This paper does not say. KV-Skill measures Qwen3.5-4B LiveMath Base at 32.3 with a larger output budget, against 22.4 here. With that base the LiveMath gain shrinks from +32.4 to +22.5.
- No cost numbers of any kind: no tokens, no dollars, no teacher calls counted.

## Untested assumptions

- That a student pass after a patch is caused by the patch.
- That passing the source task means the rule transfers. Transfer is only seen in the aggregate test score.
- That a text rule is the right carrier. No other form is tried.
- That putting the whole library in the prompt keeps working as the library grows.
- That the two groups show generality across student strength. They differ in teacher too.
- That added rules do no harm to tasks already passed.

## Overlap with Loopy (K1 to K6)

- K1, text vs executable from the same failure, teacher and student: **not covered**. Text only. It does cover the note arm in detail: teacher writes a rule from the student's failure plus its own run, same task (§3.1). The paper cites AgentDistill (arXiv 2506.14728, reusable tool modules distilled from teacher runs) as related work and does not compare against it. That paper is the executable-side neighbor and is not in our lit folder yet.
- K2, student-capability axis by form: **partly, thin**. Two students, one form, and the teacher changes with the student. No analysis of form by strength. Table 1 does show every text-skill method gaining less on the stronger student.
- K3, task-difficulty axis: **not covered**. Five benchmarks, no difficulty levels. The only hint is across benchmarks: checked text patches fix 16% of failures on the code-execution benchmark, 35% on LiveMath, and 55 to 67% on SearchQA and DocVQA (my arithmetic, Tables 5 and 7).
- K4, non-text help that harms a capable student: **not covered**. No non-text form. For text, some baseline skills lower the stronger student's SpreadsheetBench score by about 5 points (Table 1), with no per-task analysis.
- K5, controls: **partly**. The keep-only-if-the-student's-re-run-passes rule is the core of the method (§3.2) and is ablated (59.0 without, 66.8 with; Table 3). Missing: a generic or placebo note, a re-roll control, and variants of a repeating task. Testing is on held-out i.i.d. instances; ALFWorld test uses unseen environments.
- K6, cost and break-even: **not covered**. It reports how often a build fails (Tables 5, 7) and library size (Tables 2, 4). No cost, no break-even.

Plain answers:
- Does it compare knowledge forms on the same students? No. It compares sources of text (student-only, teacher-only, contrast, contrast plus re-run), all as prompt text.
- How many students, what strength? Two. Qwen3.5-4B (No Skill average 43.5) and Qwen3.6-35B-A3B (57.9). Each has a different teacher.
- Does any form help weak models more than strong ones, or the reverse? For text, the weaker student gains more points with every method in Table 1 (SKILL-KD +23.3 vs +16.7). For SKILL-KD the share of remaining room closed is the same (41% vs 40%). The authors do not analyze this and the teacher confound stays.
- Any case where a form hurts? SKILL-KD never drops below No Skill on test. Baseline text skills do in five cells, most clearly EvoSkill on Group 1 DocVQA (-7.2) and EvoSkill and Trace2Skill on Group 2 SpreadsheetBench (-5.3, -5.0). §5.4 describes a later patch weakening an earlier rule.

## What we can no longer claim

- That the tailored checked note is a new protocol. A teacher note written from the student's failure and kept only if the student's re-run passes is §3.2 of this paper. Our note arm is SKILL-KD with one round and no consolidation.
- That checking a note by re-running the student is our idea, or that we are first to show it matters (Table 3).
- That a note written from the teacher's success alone transfers worse than one written from the gap (Table 2).
- That a teacher need not solve the task to write a useful note (Table 5).
- That a checked text note fixes only a minority of a weak student's failures is surprising. It can be read off Tables 5 and 7 here (pooled about 30% after one round, 41% after three, 16% on the code benchmark), though the paper never frames it as a fix rate.
- That text has a ceiling and tools may be needed beyond it. The authors say so in their limitations. They do not test it.

## What stays open

- The head-to-head: note vs function, same failure, same teacher, same student. Nobody here runs it.
- Whether the note's 16% fix rate on a code-execution benchmark is where a function wins. This paper gives the text side only.
- A real student-strength axis with the teacher held fixed, and whether the best form flips along it.
- A difficulty axis inside one task family.
- Harm counts: tasks passed alone, failed with help.
- A generic-note placebo and a plain re-roll control. Both are missing here, so Loopy's 11% generic and its variant testing answer a hole this paper leaves.
- Testing on variants of the same scenario instead of the instance the note was written from.
- Cost per build, failed builds, break-even over repeated uses.
- Follow-ups from the reference list that bear on K1: AgentDistill (2506.14728) and Kang et al. 2025, "Distilling LLM agent into small models with retrieval and code tools". SkillOpt (2605.23904) for the validation-gated text baseline both papers lean on.
