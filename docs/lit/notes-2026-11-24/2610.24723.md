# 2610.24723 · Where Natural Language Ends in Agents: Executable Skill Composition with MetaSkill

- arXiv v1, 17 Oct 2026, cs.AI. Workshop paper (LP4FM). Shu, He, Zhou, Liu, Han, Wang (TokenRhythm Technologies; Xidian; BIT). Code: github.com/TokenRhythm/opensquilla.
- Read on 2026-11-24 from the arXiv HTML text dump (640 lines, all of it). Figures were read as text in the dump, not viewed in the PDF.

## Claim

When several text skills must work together, keep the judgment inside each skill as language, and make only the hand-offs executable: which skill runs after which, and which earlier output is passed on. A small runtime runs that graph. Key number: against showing the same graph to the agent as prompt text, the executable version wins a blinded pairwise preference of 0.658 (95% task interval 0.575 to 0.742) on DeepSeek-V4-Flash (Table 1). On GLM-5.2 the same comparison is 0.550 (0.425 to 0.667), which includes parity.

## Method

- One frozen plan per task. Three ways to give it to the agent: prose procedure (NL-SOP), the graph shown in the prompt (Prompt Graph), the graph run by a runtime (MetaSkill). Same skills, same backbone, same host harness (Section 4.2, Figure 2).
- Runtime: checks the graph, starts a node when its predecessors are done, pastes named predecessor text (cut at 6,000 characters) into the next call, each call in a fresh context (Section 3.2).
- 20 AgentSkillOS tasks that use two to four skills. 3 runs per task and condition. Two backbones: GLM-5.2 and DeepSeek-V4-Flash.
- Outcome: a fixed judge (Claude Opus 4.5, temperature 0) compares two artifacts in both orders. Win 1, tie 0.5, loss 0. Interval from 10,000 task-level bootstrap resamples.

## Results, including the weak ones

- Table 1: MetaSkill vs NL-SOP 0.567 (0.433 to 0.692) on GLM-5.2 and 0.558 (0.467 to 0.650) on DeepSeek-V4-Flash. Both include parity. Only the Prompt Graph row on DeepSeek excludes it.
- Table 2: vs AgentSkillOS with the same skills, 0.542 (0.425 to 0.650). Includes parity.
- Table 3: vs three agent stacks. Only OpenClaw excludes parity (0.625, 0.525 to 0.725).
- Trace audit on GLM-5.2: 264 of 264 nodes complete, 0 of 282 order violations.

## Limits

- Theirs: no skill retrieval; one judge.
- Mine: no task success measure, only preference. No weak model. No teacher and student. The plan is written once by the authors, not learned from a failure. Most intervals include parity.

## Overlap with Loopy

- K1 (note vs function, same failure, teacher and student): not. It compares prose and executable forms of the same plan, but for coordination between skills, on one model that both plans and executes.
- K2 (student strength axis): not. Two backbones, both mid to strong, no trend reported.
- K3 (task difficulty): not. K4 (harm to capable students): not. K5 (controls): partly, the three conditions come from one frozen plan. K6 (cost): not.

## What it means for us

Nothing to give up. It is a neighbor that supports the general idea "make the mechanical part executable, leave judgment in language", measured on strong models with a soft outcome. Cite it as related work on form.
