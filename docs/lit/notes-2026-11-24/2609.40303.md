# 2609.40303: How Much of a Harness Does a Strong Agent Need for Autonomous ML Engineering?

arXiv 2609.40303v1, 30 Sep 2026 (PDF dated 1 Oct 2026), cs.AI. 45 PDF pages (9 main, references, appendix A to G). Kirill Brilliantov (1, 2, equal), Alejandro Hernández-Cano (1, 2, equal, work done while interning at Apple), Emmanuel Abbé (1, 2). 1 EPFL. 2 Apple.

In one line: on MLE-bench (30 Kaggle tasks, 24h, one A100) and NatureBench, a single long coding-agent session with three small tools ("Malena") matches or beats search trees, multi-agent orchestration and four published MLE harnesses at frontier backbones. The one exception is the weakest backbone tested (Gemma 4 31B), where the most structured harness (MLEvolve) wins on percentile. No teacher, no student, no text vs code comparison of the same knowledge.

Figure numbering note: the arXiv HTML text drops one caption (the search-strategy plot), so its figure numbers run one lower from that point. Below I use the PDF numbers (Fig. 1 to 15).

## Claim (key numbers and where they are)

1. The coding-agent environment is the largest effect. Single-iteration percentile rises from Chat to Oneshot by roughly 15 points for GLM 5.2 and 12 for Kimi K3, DeepSeek V4 Flash and Pro (Fig. 2, §4.1; values read from the plot).
2. Tree search over Oneshot iterations does not matter. No pair of Chain, Greedy, UCB1, Best-of-N differs significantly; largest gap UCB1 over Best-of-N, 2.71 percentile points, 95% CI (-1.44, +6.60) (§4.2, Table 5).
3. A single autonomous session (Malena) beats manual search on medal rate: +11.9 vs Best-of-N, +6.6 vs UCB1, +6.6 vs Greedy, +7.7 vs Chain, all significant (Table 5). Lowest selection gap, 1.876 points (Table 6).
4. Multi-agent add-ons do not help and can hurt: base vs +B+P3 (parallel plus broadcast) is +7.59 percentile, +22.4 medal in favour of base, significant (Table 10, Table 1).
5. Against four published harnesses at matched backbone, budget and hardware, Malena is never significantly worse at the three frontier backbones. At GLM 5.2 it beats all four on both metrics; medal 62.5% vs best external 47.1% (AiScientist) (Table 15, Table 16, §6).
6. At Gemma 4 31B, MLEvolve beats Malena by 10.53 percentile points (CI -14.72 to -6.36, significant); medal -4.4, not significant (Table 16).
7. NatureBench surpassed-SOTA rate: GLM 5.2 Malena 21.7 vs AiScientist 17.5 vs MLEvolve 10.8; Kimi K3 26.7 vs 27.1 vs 11.7 (Table 2).
8. Malena is pricier in tokens: $12.12 mean per run at GLM 5.2 vs $1.95 AiScientist, driven by cache reads from one growing session. Hardware dominates ($24 to $85 per 24h A100) (§5.1, Fig. 4).

## Method, in enough detail to reproduce

Framework (§3, B.2). OpenCode v1.15.6. Default tools kept except doom_loop, plan_exit, question disabled. Native bash replaced by a version with a 24h timeout, per-command resource stats, an OOM watchdog, and a command whitelist (pwd, ls*, python*, nvidia-smi and more). Other tools: read, write, edit, task (blocking subagents), todowrite. Backbones served locally with vLLM at max reasoning effort and canonical max sequence length (A.4). Agent resources: 1 x A100 80GB, 12 CPU cores, 144GB RAM.

Iterations (B.1). All from one prompt template family (persona, "scientific-approach questions", resource and time line, general tips).
- Chat: one completion, no tools. Gets task text plus a harness-built data overview (directory tree, CSV column stats, JSON schemas, file heads, sample submission head). Must output a full script. Script runs once with the remaining budget. On failure, re-prompt in the same conversation with failure reason, truncated stdout/stderr, hardware summary; repeat until a valid submission.
- Oneshot: one coding-agent session, one turn. Gets only data paths. Must use cheap verification runs, then exactly one production run. Must deliver main.py, submission.csv, design.md, score.txt; harness re-prompts until all exist. With a parent node, an "improve" variant reads the parent's design.md and decides refine vs pivot. 6h limit.
- Malena: the same environment, one session for the whole budget, re-prompted with remaining time whenever a turn ends. No single-run or documentation rule. Tools: submission_register / submission_list (agent registers submissions with its own validation score; no test score is ever shown), system (resources, time left), jobs (job_submit, job_wait, job_queue, job_info; when on, every bash call is capped at 10 min).

Search strategies (§4.2, B.3). Chain: parent = latest node. Greedy: parent = best validation node. UCB1: global supremum over all nodes of rank(max subtree score)/(|V|-1) + c sqrt(ln(|V|+1)/(|C(n)|+1)), c = 0.75. Best-of-N: independent Oneshot runs packed into 24h by effective time, bootstrapped into trajectory sets.

Interventions ablated (§4.4, B.2). D delegation (task tool plus prompt nudge). P3 three parallel Malena sessions on one machine. B broadcast tool with P3. N time nudges at 25/50/75/90%. R resource nudge when CPU or GPU < 50% (5 min spacing). H HuggingFace Hub search MCP. V strict validation guidelines in prompt. I minimal prompt. s eight skills loaded on demand (submission-blueprint, quick-strong-baseline, cost-saving-techniques, simplification-probe, ablation-probe, runtime-estimate, stagnation-pivot, cross-iteration-synthesis). BI baseline iteration (shared validation workspace). HV hidden validation split (not deployable, a ceiling).

External harnesses (§5, D.1, D.3). MLEvolve (UCT tree with six operators, decaying exploration, BM25+FAISS memory, three candidates per GPU, greedy commit on LLM-extracted validation score). AiScientist (single conversation, file-as-bus markdown logs, agent picks final submission). Arbor (Coordinator/Executor over an Idea Tree, 3 parallel executors, 4h per experiment, stop_after = 8). ScienceFlow (YAML manifest, parallel workers, LLM-based resource admission). Bug fixes applied for GLM 5.2 tool-calling. MLEvolve on DeepSeek V4 Flash run at medium effort because max starved it of search steps (Table 17).

Tasks (A.1 to A.3). MLE-bench: 30 tasks from the GPT-5 system card set, bms swapped for alaska2 (5 Lite, 21 Medium, 4 High). default29 = 29 original tasks without bms or alaska2 (used in §4). fixed30 = 30 tasks with four prepare.py bugs fixed (champs missing test geometry; hubmap, smartphone, multi-modal leaked test labels; diffs in A.2). fixed14 and fixed10 = hard subsets made by dropping tasks Gemma 4 31B solved and tasks Kimi K3 never solved. NatureBench: 40 Nature-family tasks, 8h budget (double the published 4h), unlimited /evaluate calls, surpassed if normalized gain g > 0.1.

Seeds (G.1). 3 to 4 seeds per task at 24h; 6 to 10 at 6h and for Chat.

## Setting, data, models

Nine backbones in Fig. 2: GPT OSS 120B, Agents A1, Gemma 4 31B, DeepSeek V4 Flash (Preview), DeepSeek V4 Pro (Preview), DeepSeek V4 Flash, DeepSeek V4 Pro, GLM 5.2, Kimi K3. Five in the Malena vs Best-of-N backbone test (Table 8). Four in the harness comparison (Kimi K3, GLM 5.2, DeepSeek V4 Flash, Gemma 4 31B; Table 15). Two on NatureBench. Default backbone GLM 5.2. Strength ordering (by Chat or Malena percentile): GPT OSS 120B and Agents A1 lowest, Gemma 4 31B next, DeepSeek Preview releases, DeepSeek finals, GLM 5.2, Kimi K3 highest.

## Metrics (exact definitions)

- Percentile: share of human leaderboard entries that score worse than the agent (§3).
- Medal rate: share of tasks with any medal (bronze or better).
- Self-select: the submission with the best agent-reported validation score. Oracle: the one with the best hidden test score. Selection gap = oracle minus self-select.
- Macro-task average (A.5): mean over tasks of the mean over seeds. A run with no valid submission counts as no medal and worst percentile (Table 15 caption).
- 95% CIs: bootstrap over seeds within each task, task set held fixed (A.5). So CIs reflect seed noise only, not task sampling.
- Paired-by-task difference (A.5): mean over tasks of (mean A minus mean B); significant if the bootstrap CI excludes 0, marked *. "won A/B/=" counts tasks where A or B is higher or they tie.
- NatureBench: surpassed-SOTA rate = share of tasks where the best score anywhere in the run (oracle) has g > 0.1.
- Cost: OpenRouter Sept 2026 effective prices; cache reads priced at 0.1 x input as a fixed assumption, not measured (A.4).

## Results, including weak and negative ones

Chat vs Oneshot (Fig. 2, my plot reading, about +/- 1 point). Single-iteration percentile Chat then Oneshot: GPT OSS 120B about 25 then 20; Agents A1 about 23 then 22; Gemma 4 31B about 30 then 31; DeepSeek V4 Flash (Preview) 33 then 37; DeepSeek V4 Pro (Preview) 39 then 40; DeepSeek V4 Flash 38 then 53; DeepSeek V4 Pro 39 then 53; GLM 5.2 40 then 55; Kimi K3 48 then 60. Medal rate shows the same: GPT OSS 120B about 10.5% Chat vs 5.5% Oneshot, Agents A1 about 10% vs 7.5%. So the tool environment lowers single-iteration scores for the two weakest models and is near zero for Gemma and the Preview releases. The text says "even weaker models such as Gemma 4 benefit" and does not mention the two weakest models doing worse. The Gemma benefit is only visible in the Best-of-N squares (about 30.5 vs 35 percentile).

Search (Table 5, Table 6, Fig. 3). All four search methods within CIs. Best-of-N has the largest selection gap (6.832). Self-select percentiles: Malena 69.30, UCB1 66.92, Greedy 66.19, Chain 64.72, Best-of-N 64.21.

Selection-gap fixes (Table 7, Oneshot, GLM 5.2, 12h). BI shrinks the gap to 2.024 but lowers oracle to 63.26 (from 67.99). V gives best self-select 63.74. HV gap 4.479. Authors say power is too low for strong conclusions.

Malena budget scaling (Fig. 8, DeepSeek V4 Pro Preview, bare Malena, oracle only). Final oracle percentile about 42 (3h), 46 (6h), 48 (12h), 50 (24h). At the same wall-clock time, shorter-budget runs are higher (at 3h, the 3h-budget run is about 42, the 24h-budget run about 22). The authors read this as the agent pacing itself to its budget.

Malena vs Best-of-N by backbone (Table 8, Fig. 9). Percentile delta: Gemma 4 31B -3.97 (significant, Best-of-N better), DeepSeek V4 Flash +1.15 (ns), DeepSeek V4 Pro +9.39*, GLM 5.2 +5.52*, Kimi K3 +4.51*. Medal delta: Gemma +7.9*, Flash +3.3 (ns), Pro +12.8*, GLM +12.0*, Kimi +10.5*. At Gemma the two metrics disagree in sign. The authors offer two explanations: weaker models use autonomy less well, or Gemma's 256k context forces lossy compaction. Not separated.

Malena infrastructure (Table 9, Table 10). At 24h on default29 (GLM 5.2): adding time nudges hurts (base vs +N +5.46 percentile*, +10.6 medal*, 8/1/20). Removing system and jobs hurts medal (+8.9*). Removing jobs alone is slightly better (-1.17, ns). On fixed14 at 12h, on top of +N: +R resource nudge hurts (+7.76 percentile* in favour of no R); D, P3, B+P3, D+H+V and s (skills) are all ns. The eight text skills do nothing measurable (+N vs +N+s: +0.79 percentile, +2.2 medal, ns).

Oneshot infrastructure (Table 13, Table 14). For Oneshot the picture is different. GLM 5.2: +H helps (base vs +H -1.93*), all of S+J+N+H+D+V together helps (-2.80 percentile*, -5.0 medal*). DeepSeek V4 Pro (Preview): minimal prompt I helps (base vs +I -4.10*), i.e. removing guidance text raised scores. So harness additions help the less autonomous unit (Oneshot) but not the autonomous one (Malena).

Orchestration (Table 1, fixed14, 24h). base 66.51 percentile, 55.7 medal; +D 63.62, 45.2; +P3 67.77, 52.4 (oracle 71.79, highest ceiling); +B+P3 58.91, 33.3. Only +B+P3 is significantly worse (Table 10).

Context cap (Table 11, Table 12, fixed10, GLM 5.2, n = 40 runs per arm). 64k cap with compaction: 9.5 compactions per run on average (3 to 63), each drops about 76% of context. Self-select medal 57.5% (1M) vs 50.0% (64k), percentile 77.1 vs 73.5; oracle medal 65.0% vs 50.0%. CIs overlap.

External harnesses (Table 15, Table 16, Fig. 1). Self-select percentile, Malena vs others:
- Kimi K3: Malena 72.75; Arbor 68.46; AiScientist 64.15; MLEvolve 63.89. Paired: +4.29*, +8.60*, +8.85*. Medal vs Arbor +0.0 (ns).
- GLM 5.2: Malena 69.74; Arbor 59.26; AiScientist 61.39; MLEvolve 54.32; ScienceFlow 47.59. All paired deltas significant (+10.48, +8.36, +15.42, +22.16).
- DeepSeek V4 Flash: Malena 58.53; Arbor 61.23; AiScientist 59.13; MLEvolve 42.53; ScienceFlow 49.99. Malena vs Arbor -2.71 (ns), vs AiScientist -0.60 (ns), vs MLEvolve +16.00*, vs ScienceFlow +8.54*.
- Gemma 4 31B: Malena 32.35; AiScientist 33.00; MLEvolve 42.88 (oracle 50.73). Malena vs MLEvolve -10.53*, vs AiScientist -0.65 (ns).
The text of §5.1 says Malena "matches or beats every harness on every tested pair" and then concedes Gemma; Table 16 shows one significant loss.

Structure by strength, MLEvolve minus Malena in percentile (Table 16): Gemma +10.53, DeepSeek V4 Flash -16.00, Kimi K3 -8.85, GLM 5.2 -15.42. A crossover between the weakest backbone and the rest. The authors name this directly: "weaker backbones still benefit measurably from hand-designed workflow priors like MLEvolve's tree search" (G.2, contributions §1).

NatureBench (Table 2, Table 21). Oracle metric with unlimited grading calls. MLEvolve calls /evaluate less (median 8 vs 16 Malena, 18 AiScientist), which the authors say mechanically disadvantages it.

Tuning of baselines (D.3, Tables 17 to 20). MLEvolve max vs medium effort on DeepSeek V4 Flash, 10 tasks: medal 0.0% vs 25.0%, nodes per run 18.5 vs 62.8, buggy-node rate 61% vs 62%. So about 61% of MLEvolve's built candidates fail to run, at either setting. ScienceFlow 1 vs 2 workers: ns. resource_smart_policy vs llm: ns. Arbor 12h timeout and no early stop: ns (CIs as wide as 0 to 100 on tiny subsets).

Difficulty (D.5, Fig. 11). Tasks grouped into four clusters by perceived difficulty across harnesses (5, 8, 7, 10 tasks). Backbone not stated. Malena's lead is largest on cluster 3 (end about 93 vs about 70 to 74), smaller on cluster 4 (about 30 vs 20 to 27), and absent on cluster 1 (all near 100). On cluster 2, MLEvolve ends slightly above Malena (about 88 vs 85) by my reading, though the text says both lead. No numeric CIs or tests per cluster.

Trace analysis (§5.2, E). GLM 5.2 judge labels techniques at checkpoints on 10 tasks, 13-way taxonomy, embedding clustering (Qwen3-Embedding-8B, cosine 0.70), LLM split and merge review, then relabel. Malena and AiScientist shift toward ensembling, model selection and post-processing late in the run; MLEvolve stays flat after about 10% (Fig. 6). Rarity medians: MLEvolve 0.80, Malena 0.75, AiScientist 0.74, Oneshots 0.65 (Fig. 5 legend). So MLEvolve, not Malena, has the rarest techniques by median.

Contamination (F, Table 22). Dolos containment: Malena-vs-real p99 0.020 vs real-vs-real 0.453; zero of 924,750 pairs flagged. Embedding Chamfer p99 0.746 vs 0.882.

## Limitations

Theirs (G.1): MLE-bench contamination risk (mitigated by fixes, Dolos and embedding checks, NatureBench); low power (3 to 4 seeds at 24h); coordination research mostly out of scope; possible tuning asymmetry in favour of their own system (mitigated by D.3).

Mine:
- CIs bootstrap seeds only, with tasks fixed. They say nothing about new tasks. With 14 to 30 tasks, a few tasks can swing paired deltas (the paper notes failure imputation gives large gaps outsized leverage, D.2).
- fixed14 and fixed10 are chosen using Gemma and Kimi results, which can bias comparisons that involve those models.
- The capability crossover rests on one weak backbone (Gemma 4 31B) in the harness table. The two weakest models of Fig. 2 were not run through the harness comparison.
- Gemma's percentile and medal metrics disagree in sign vs Best-of-N, so "which form is better for weak models" depends on metric.
- Context length (256k for Gemma) is confounded with capability.
- The text overstates in places: "even weaker models such as Gemma 4 benefit" (Fig. 2 single iterations show no gain; GPT OSS and Agents A1 drop); "matches or beats every harness on every tested pair" (Gemma loss). The rarity claim (Malena in the top two) is true, but MLEvolve has the higher median, which the trace-analysis narrative underplays.
- Cache cost is a modelled 0.1 x input, not measured.
- Fig. 11 has no backbone label and no per-cluster test.

## Untested assumptions

- That "agentic capability" from post-training, not scale or context length, drives who benefits from structure. Suggestive DeepSeek Preview vs final evidence only (G.2).
- That the selection gap comes from incomparable validation splits across runs (stated as a hypothesis, C.3).
- That MLE-bench percentiles reflect real engineering skill after their four fixes.
- That the eight skills and other prompt additions were written well enough to be a fair test of "text guidance".

## Overlap with Loopy (K1 to K6)

- K1 (same failure, same teacher, same student, text vs code head to head): not covered. No teacher, no failure-specific artifact, no comparison of one piece of knowledge as text vs code. The nearest items are text skills (s) and prompt guidelines (V) vs tools (H, jobs) added to the same agent, which are different knowledge.
- K2 (student-capability axis, form by strength interaction): partly. Strong evidence of a structure by capability interaction, but for harness structure, not for the form of teacher help. MLEvolve minus Malena: +10.53 percentile at Gemma 4 31B (significant), -8.85 to -16.00 at the three stronger backbones (Table 16). Chat to Oneshot gain: negative for GPT OSS 120B and Agents A1, near zero for Gemma, +12 to +15 for frontier models (Fig. 2). Malena vs Best-of-N flips on percentile at Gemma (Table 8). Four to nine backbones depending on the experiment.
- K3 (task difficulty axis): partly, weak. Fig. 11 splits tasks into four difficulty clusters; Malena's lead is largest on the second-hardest cluster and smallest on the easiest. Harness vs harness only, no text vs executable form, no CIs.
- K4 (harm to capable students from non-text help): partly. Adding structure to a strong agent hurts in several significant cases: time nudges (-5.46 percentile, -10.6 medal), parallel plus broadcast (-7.59, -22.4), resource nudges (-7.76), and all four external harnesses at GLM 5.2. Per-task counts exist as won A/B/= (e.g. base vs +N: base better on 8 tasks, +N better on 1). Not pass/fail on tasks the model solved alone, and the help is harness structure, not a teacher-written function.
- K5 (controls): not covered. No placebo artifact, no keep-only-if-rerun-passes gate (self-selection on validation is the nearest), no repeating-task variants.
- K6 (cost and break-even, counting failed builds): partly. Token and dollar cost per run per harness (Fig. 4, Fig. 10), hardware cost, and a failed-build rate for MLEvolve (61 to 62% buggy nodes, Table 17). No amortisation over repeated uses, no break-even.

Plain answers:
- Does it compare a natural-language form with a program form of the same knowledge on the same models? No.
- Across how many models and of what strength? Nine in Fig. 2 (GPT OSS 120B up to Kimi K3), five in Table 8, four in the harness comparison (Gemma 4 31B, DeepSeek V4 Flash, GLM 5.2, Kimi K3), two on NatureBench.
- Does more structure help weak models more than strong ones, or hurt strong ones? Yes, both, for harness structure. Weak: MLEvolve's tree search beats the plain session at Gemma 4 31B by 10.53 percentile points. Strong: the same harness loses by 8.85 (Kimi K3), 15.42 (GLM 5.2), 16.00 (DeepSeek V4 Flash). Adding nudges or parallel agents to the strong plain session costs 5 to 8 percentile points and up to 22 medal points. In the other direction, giving the model more autonomy (tools) helps strong models (+12 to +15) and hurts the two weakest (about -1 to -5 percentile, my plot reading).
- Any analysis by task difficulty? Yes, one (D.5, Fig. 11), harness vs harness, descriptive only.

## What we can no longer claim

- That "hand-built structure helps weaker models and stops helping or hurts stronger ones" is a new finding in agent work. This paper shows it for MLE harnesses across four backbones with paired CIs, and states it as the bitter-lesson reading (G.2).
- That generic text guidance (skills, guidelines) added to a strong agent adds nothing measurable is new. Their eight skills and validation guidelines are ns on Malena (Table 10).
- That adding helpful-looking scaffolding can significantly hurt a capable agent is new. Time nudges, resource nudges and broadcast all hurt significantly (Table 10).

## What stays open

- The form question itself: the same failure-derived knowledge given as a short checked note vs an executable function, same teacher, same student.
- Whether the capability crossover holds for teacher-built artifacts (note vs function), not only for harness structure.
- Per-task breakage: tasks a capable student passed alone and fails with the artifact.
- Placebo note control and a keep-if-rerun-passes gate.
- Text fading vs code holding across difficulty.
- Build cost including failed builds and break-even over repeated variants of one task.
- Any of this in an API-task setting like AppWorld; this paper is long-horizon ML engineering only.
