# The Memory Trust Gap: Reliance on Stale Evidence Across Model Scales in LLM Agents

arXiv 2609.01852, v2, 16 Nov 2026 (cs.AI). NeurIPS 2026 workshop PALM (Personalized, Aligned, Long-Term Memory for AI Systems).
Authors: Jundong Hu (corresponding; led the work end to end) and Shekar Ramachandran (supervision, compute). Both PayPal AI.

## Claim

LLM agents follow a stale stored note at every size tested. Whether that turns into harm against a no-memory baseline depends on the cue. Larger Qwen3 checkpoints resist a plain stale note but are harmed the most when the note is dated newer than the authoritative value.

Key numbers:
- Benefit suite stale-value reliance 0.92 / 0.99 / 1.00 / 1.00 for Qwen3 0.6 / 1.7 / 4 / 8B; paired Delta_mem -0.33 / -0.35 / -0.35 / -0.37, all CIs below 0 (Section 4.1, Table 2, Figure 1).
- explicit_conflict reliance (stale and correct both stored) 0.50 / 0.50 / 0.01 / 0.00 (Table 2).
- Safety suite at L0: only 0.6B is harmed (Delta_mem -0.18, reliance 0.19); others 0.00 (Table 2).
- Trap sweep: at L3 the 8B model has reliance 1.00 and Delta_mem -1.00; at L2 the 4B has reliance 0.83 (Section 4.2, Table 3, Figure 2).
- Recency effect is larger on larger models: 8B minus 0.6B = +0.302 [0.269, 0.336] (Table 6).
- Position effect flips sign: +0.22 at 0.6B to -0.11 at 8B; 8B minus 0.6B = -0.326 (Tables 5, 6).
- Mitigation: metadata gains +0.30 / +0.28 / +0.53 / +0.54 and recovers only 4B/8B (0.90 / 0.95); pre-resolving the conflict reaches 0.95 / 1.00 / 1.00 / 1.00 at every size (Section 6, Table 7, Figure 4).

## Method (enough to reproduce, as far as the paper allows)

Benchmark (Section 3, Appendix A).
- 300 base scenarios, 150 per suite, from 33 template families. Expanded from a 56-scenario pilot by a deterministic curated-pool generator. Frozen v1, SHA-256 pinned. Authors reviewed all 300 by hand.
- A base scenario is a templated situation (for example a room booking) with one ground-truth action and slot values. Scenarios sharing a template but drawing other slot values form a template family.
- Benefit suite (A): the task needs the stored fact ("book my usual airline"). No current context, so no-memory is at chance.
- Safety suite (B): an "authoritative tool" always holds the correct value. It is static prompt text, a dated [CURRENT CONTEXT] entry, not an executed tool call. No-memory is at ceiling.
- Four memory conditions: no_memory, clean (memory agrees with truth), stale (memory holds an old value), explicit_conflict (both old and correct values stored) (Table 1).
- Each item produces a constrained action among 3 options. Scoring by exact, regex or canonical match against the construction-time truth. No LLM judge. Manually checked on a random sample.
- Circular option-permutation averaging: every scenario is scored under each cyclic rotation of the 3 options, then averaged.

Trap sweep (Section 4.2). Levels L0 to L3 make the stale note "increasingly plausible (e.g. inflating its apparent recency)". The exact content of each level is not specified anywhere in the paper.

Factorial (Section 5.1, Table 4). On the Safety suite, four binary features of the stale note, all 16 cells per scenario:
- label: under a [NOTES] label (off) vs label removed (on).
- recency: dated older than current (off) vs dated newer (on).
- authority: plain source (off) vs inflated or official source (on).
- position: placed last (off) vs placed first (on).
Main effect = mean reliance over the 8 "on" cells minus mean over the 8 "off" cells.

Dose-response and probes (Section 5.3, Figure 3, Figure 6). Recency gap swept from -365 to +365 days. Probes ask the model which note is newer, which source is more authoritative, and which note is first-hand from the user. The [AUTHORITATIVE] marking test follows Reddy and Challaram 2026.

Representation comparison (Section 6). Same conflict in three forms: raw (both items, unmarked), metadata (each item annotated with provenance and timestamp), representation-oracle (stale item removed). The number of scenarios used here is not stated.

Validation (Section 7). Same machinery on RGB (Chen et al. 2024) and MisBench (Peng et al. 2025); MisBench 6 styles x 2 hop depths; Llama-3.2-1B/3B-Instruct and Llama-3.1-8B-Instruct; a framing control rendering the same wrong item as [MEMORY], [DOCUMENT] or [EARLIER MESSAGE]; thinking mode on at 0.6B and 8B.

Models and decoding (Appendix A). Qwen3 0.6B, 1.7B, 4B, 8B, non-thinking unless stated. Greedy decoding, identical prompts. Plain transformers on A100 40GB MIG slices, one model per slice. Benchmark and harness not yet released ("pending internal approval").

Statistics. Unit = base scenario. 95% percentile bootstrap over scenario ids. Cross-size interactions by bootstrapping paired differences. Robustness: template-family cluster bootstrap (CIs widen 1.1 to 2.2x, nothing crosses 0) and leave-one-family-out (Benefit estimate moves at most 0.012). Exploratory, not preregistered.

## Setting, data, models

Static single-turn prompts with a stored note and, in the Safety suite, a dated authoritative entry. Closed set of 3 actions. Synthetic personalized-assistant scenarios (rooms, airlines, gates, cities). One family as the main size series (Qwen3 0.6 to 8B), Llama 1 to 8B as a cross-family check. Size range capped by GPU slice memory.

## Metrics (exact definitions)

- reliance = P(model action = stale value), after circular averaging.
- Delta_mem = acc(condition) minus acc(no_memory), paired per scenario. Negative = net harm relative to having no memory.
- rho* = the smallest trap level whose stale Delta_mem CI upper bound is below 0 (first level of significant net harm).
- Factorial main effect = mean reliance with feature on minus mean with feature off, over the other 3 features.
- Representation gains: meta_gain = metadata acc minus raw acc; oracle_gain = oracle acc minus raw acc.

## Results, including weak and negative ones

Benefit suite (Table 2). No-memory 0.35 to 0.37 (chance 0.33). Clean 0.94 / 0.99 / 1.00 / 1.00. Stale reliance 0.92 to 1.00. explicit_conflict reliance drops from 0.50 at small sizes to about 0 at 4B and 8B.

Safety suite (Table 2, Table 3). No-memory at or above 0.98 everywhere. L0 reliance 0.19 / 0.00 / 0.00 / 0.00. L1 0.48 / 0.43 / 0.09 / 0.02. L2 0.43 / 0.45 / 0.83 / 0.94. L3 0.63 / 0.72 / 0.93 / 1.00. rho* = 0 / 1 / 1 / 1, so the threshold separates only 0.6B from the rest; it is not monotone in size.

Factorial (Table 5). label +0.23 / +0.39 / +0.30 / +0.32 (all sizes, no group trend: large minus small +0.005 ns). recency +0.26 / +0.15 / +0.52 / +0.56. authority +0.13 / +0.11 / +0.12 / +0.14 (flat, no interaction). position +0.22 / -0.01 (ns) / -0.14 / -0.11.

Dose-response (Section 5.3). Recency is a step: reliance jumps once the stale note is at least 1 day newer, then saturates. 4B and 8B read dates almost perfectly in the probe (about 0.9 to 1.0) and are the ones exploited. Authority grows with size only when recency is neutral. [CURRENT CONTEXT] label on the user's own statement brings 8B reliance to 0 in the provenance flip. [AUTHORITATIVE] marking cuts reliance at +1 day by 0.42 (4B), 0.33 (8B), 0.06 (0.6B), 0.00 (1.7B). A verbal "prefer the newest authoritative source" rule has little effect and raises reliance in some settings.

Mitigation (Table 7). Raw acc 0.49 / 0.43 / 0.37 / 0.41. Metadata 0.79 / 0.72 / 0.90 / 0.95. Oracle 0.95 / 1.00 / 1.00 / 1.00. Gains CIs are wide (for example 8B meta_gain [0.38, 0.70]).

External (Table 8, Figure 7). Pooled reliance 0.81 to 0.94. Net harm only where the closed-book baseline is nonzero: RGB pooled Delta_mem +0.02 (0.6B, ns), -0.14 (4B), -0.32 (8B); RGB free-text -0.17 (1.7B), -0.37 (8B). MisBench closed-book is near 0, so its Delta_mem is near 0.

Style sweep. Spread across 6 styles at most 0.19 per model; blog is least trusted in all 8 hop x model cells (sign test p about 0.004).

Cross-family (Table 9, Table 10). Llama 1B / 3B / 8B Benefit reliance 0.462 / 0.960 / 1.000, Delta_mem -0.098 / -0.307 / -0.360. Parse rate as low as 0.851 (1B no_memory). Position is negative at 3B and 8B; the positive position effect at Qwen3-0.6B does not reproduce, so the sign reversal is Qwen-specific. Llama 1B label effect is null.

Framing control (Table 11a). reliance(memory) minus reliance(document) = -0.311 / -0.058 / -0.013 / +0.016 (ns). A stale document is trusted more than a stale memory at the 3 smaller sizes. Memory is trusted more than an earlier message at all sizes. So the failure is not memory-specific.

Thinking mode (Table 11b). 0.6B reliance rises 0.924 to 0.991 (+0.067 [0.040, 0.096]). 8B unchanged at 1.000.

Weak spots inside their own data.
- rho* = 1 for 8B rests on a Delta_mem of about -0.02 at L1 (Figure 2, right). "Significant net harm" there is tiny.
- Over-trust in the Benefit suite is following the only information available. With no current context, following the note is the expected action, not a checking failure.
- In the trap levels the stale note is made to look newer than the "authoritative" entry. Calling the newer-dated note wrong is a definition of the benchmark. A model that prefers newer evidence is doing what many users would want.
- Evidence that "reading the cue better" drives harm rests on 4 checkpoints in a scatter (Figure 6).

## Limitations

Theirs (Section 8): Benefit suite cannot show net harm on explicit_conflict. Closed-set, action-scored design limits generality (partly offset by RGB free text). One main family; Llama reproduces only selected effects at larger sizes. Size is an observational index over separately trained checkpoints, not a capability intervention. Scenarios reviewed by the authors, not independent annotators. The "authoritative tool" is prompt text, not an executing tool. rho* depends on their level sequence. Failure is measured at consumption time, not across a write, update, retrieve memory system.

Mine:
- The trap levels are not specified, so the headline harm result (8B at L3, Delta_mem -1.00) cannot be reproduced from the paper.
- The ground truth treats an older "[CURRENT CONTEXT]" entry as correct over a newer-dated note. The harm is partly a labeling choice.
- 3-option closed set, chance 0.33, greedy decoding, one sample per prompt. No variance from sampling.
- Size range 0.6B to 8B only. No model near the frontier.
- Representation comparison has no stated n; CIs of 0.3 width.
- No agentic loop, no tool execution, no multi-step task. The agent never has a chance to check.
- Benchmark and code not released.

## Untested assumptions

- That the authoritative entry is always right and the note always wrong, whatever their dates.
- That behavior on a static prompt predicts behavior when the agent could query the tool again.
- That size stands in for capability. The authors flag this themselves.
- That the four surface features are independent; cue x cue interactions are not modeled.
- That a "note" in memory behaves like any other text advice. Their own control says a document is trusted even more at small sizes.

## Overlap with Loopy (M1 to M6)

- M1 (adopt without checking, how often): covered for stored text. Benefit reliance 0.92 to 1.00 (Table 2). Safety reliance up to 0.63 to 1.00 at L3 (Table 3). Caveat: in the Benefit suite there is nothing to check against.
- M2 (reliance vs strength): covered, with a cue-dependent answer. Larger Qwen3 rely less on a plain stale note (L0 0.19 vs 0.00) and on explicit conflict (0.50 vs 0.00), but more on a newer-dated note (L2 0.43 / 0.45 / 0.83 / 0.94; recency effect 8B minus 0.6B +0.302) (Tables 2, 3, 5, 6). Llama: 0.46 / 0.96 / 1.00 Benefit reliance (Table 9). So: stronger models rely less on obviously stale help and more on help that looks current.
- M3 (harm to a capable agent vs acting alone): covered in the Safety suite. No-memory accuracy is at least 0.98, so negative Delta_mem is a loss on tasks the model solves without the note: 0.6B -0.18 at L0; 8B -1.00 at L3 (Table 2, Figure 2). Biggest harm is on the biggest model. RGB: Delta_mem grows with size to -0.32 at 8B (Table 8).
- M4 (teacher-built task-specific function or skill): not covered. Helpers are synthetic memory notes and documents.
- M5 (text advice vs executable help): not covered. Everything is text. The framing control (memory vs document vs earlier message, Table 11a) varies only the label of text.
- M6 (mitigation): covered. Metadata helps all sizes but recovers only 4B and 8B; pre-resolution recovers all four (Table 7, Figure 4). [AUTHORITATIVE] marking helps only 4B and 8B; a verbal rule does little or harms (Section 5.3). Thinking mode does not help and raises 0.6B reliance (Table 11b).

A structural parallel worth citing: their representation-oracle removes the stale item and does the resolution for the model. It brings every size to 0.95 to 1.00, flat across size. Their metadata frame adds information the model must use. Its gain scales with size (+0.28 to +0.54). That is the same shape as Loopy's substitute (function) vs amplify (note) hypothesis, shown for memory representation, not for teacher help.

## What we can no longer claim

- That we are first to show a capable model doing worse with help than with none on tasks it solves alone (Safety Delta_mem).
- That larger models can be harmed more than smaller ones by a helper as a new finding. Shown here for recency-inflated notes and on RGB, and the paper cites ConflictBank (Su et al. 2024) for the same direction.
- That "help that does the work for the model lifts all sizes equally, while help that informs the model scales with size" is new as a general pattern. Table 7 shows it for memory conflicts. Our claim must be specific to teacher-built functions vs notes in agentic tasks.
- That verbal rules ("prefer the newest authoritative source") are a weak fix as a new finding.

## What stays open

- Executable help vs text help built from the same failure (M4, M5).
- Agentic, multi-step tasks where the student can check the helper's result and chooses not to.
- Whether a function's success equals the function's reliability for every student, measured on real student-strength gradients.
- Size beyond 8B; frontier models.
- Natural staleness (a helper written for a nearby variant) rather than templated traps.
