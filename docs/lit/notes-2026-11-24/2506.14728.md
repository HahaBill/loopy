## Claim

A strong teacher agent writes small executable tools while it solves tasks. The tools are cleaned up, grouped and merged into a "box" that a small student agent can call. No training. Key numbers (Table 2): on Game of 24, GPT-3.5-turbo goes from 34.3% to 82.7% and LLaMA3.1-8B from 21.7% to 64.0%. Qwen3-8B, already at 72.7%, goes to 79.7%.

## Method

- Teacher: Claude Sonnet 4 as manager, GPT-4o writes the tools. Only tools from runs with the right answer are kept, and only if they execute (Section 3.2).
- Box: an LLM rewrites each tool with parameters, groups tools by function, merges each group into one tool (Section 3.3).
- Student: the whole box is mounted as callable tools. The student decides whether to call, which tool, and with what arguments (Section 3.4).
- Data: Game of 24, PathVQA, SLAKE. 100 validation examples per dataset to build the box. Three students: GPT-3.5-turbo, Qwen3-8B, LLaMA3.1-8B.

## Results

- Table 2, gain per student: PathVQA +7.0, +2.3, +3.3. SLAKE +7.3, +6.7, +10.0. Game of 24 +48.4, +7.0, +42.3.
- The weaker the student on a dataset, the larger the gain. The authors put the small gain of the strong case down to a ceiling (Section 4.2).
- Table 1: students call a tool in 24% to 100% of test cases.
- Table 3: with the box, the average student matches the teacher on PathVQA (52.7 vs 52) and stays below on Game of 24 (75.5 vs 99).

## Limits (mine)

- No text arm. The same knowledge is never given as advice.
- No task is shown where the tool made a student worse. Only averages are reported.
- Tools are built from a dataset, not from one student's failure, and tested on new questions, not on variants of a repeating task.
- No cost of building the box.

## What it means for us

Teacher-made tools for a small student are prior art (this paper, and LATM, arXiv 2305.17126, before it). The fact that tools help the weakest student most is visible here but is not the paper's question. Cite both for the function arm.
