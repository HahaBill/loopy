# 2608.05475: KV-Skill: Forging Expertise in the Model's Native Language

arXiv 2608.05475v2, 12 Oct 2026, cs.LG. 20 pages. Zhaowei Han*, Xiang Zhang*, Bing Han, Kai Liu, Danqi Hu, Jie Liu (*equal contribution). University of Michigan, Ann Arbor. Code named in the paper: github.com/shawnzhg/KV-Skill.

In one line: the same skill document works much better on a small frozen model when it is loaded as a latent "operator" in the residual stream than when it is pasted into the prompt. No executable code or tool form appears anywhere in the paper.

## Claim (key numbers and where they are)

1. Same document, two forms. On Qwen3.5-4B LiveMath the SkillOpt-optimized skill scores 52.0 as prompt text and 77.2 ± 2.5 as a registered KV-Skill. SoftSkill (soft prefix) gets 64.5. The unoptimized seed text skill gets 33.1. Base is 32.3 (Table 1, §4.1). On gpt-oss-20b: 24.2 as text, 65.3 ± 0.8 registered (Table 3).
2. The text adds nothing once the operator is loaded. Operator alone 77.2, operator plus the same text in the prompt 76.6 ± 3.8 (Table 2).
3. Under matched reward training and matched parameter count, the KV-Skill substrate is best in 7 of 8 settings against soft prefix, prefix KV and LoRA (Table 5). The one loss: LoRA r=7 on Qwen3.5-4B LiveMath, 78.6 ± 2.9 vs 75.6 ± 4.1.
4. The registered operator can be cut to one direction per injection layer and keep 90 to 100% of its gain (Fig. 4, Table 9). A random direction of the same size fails (26.6 on LiveMath). A fixed coefficient instead of the query-dependent one loses 25.0 points (54.8 vs 79.8, Table 4).
5. The task lives in the operator, not the interface. Same interface, random operator 25.4, wrong-task operator 36.3, correct operator 77.2 on Qwen3.5-4B LiveMath (Table 6).
6. One shared interface serves eleven skills. Average 78.1 shared vs 77.8 with one interface per skill (Table 14, §4.5).

## Method, in enough detail to reproduce

Operator (§3.1). At each injection layer the skill is two factor matrices U and W of shape d_s x m_s (m_s slots, d_s skill dimension). M = W U^T is never built. Read(M, q) = (1/sqrt(m_s)) W (U^T q). Linear, no softmax over slots.

Interface (§3.2, Fig. 2). Query q = norm(A · RMSNorm(h)). Write-back h' = h + gamma_l · g_l · B · Read(M, q). A and B are shared across depths. Only the gate g_l and gain gamma_l differ per layer. This is a separate residual branch. It adds no prompt tokens and no entries to the attention KV cache.

Injection depths. Four (G_s = 4 in App. D.2). Fig. 2 marks relative depths z = 0.25, 0.5, 0.75, 1.0. Exact layer indices are not given.

Path 1, text-derived plus registration (§3.3, §3.4, App. A.2).
- Run one frozen prefill of the skill document. At each injection layer record the normalized residual states H (d_b x N_s, one column per skill token). Set U = W = H. The operator is H H^T. It is built per backbone.
- Registration trains only the interface. Teacher: same frozen backbone with the skill text in the prompt. Student: no skill text, operator loaded. Loss = KL(p_text || p_KV) + 0.5 · CE(p_KV, gold answer) + 0.3 · Omega, where Omega penalizes the size of the injected update.
- 300 AdamW steps per skill, learning rate 2e-4, skills registered one after another with replay of earlier ones, three seeds. The interface starts from one "pre-trained on universal skills". The paper does not say what those are.
- The Qwen3.5-4B results use one interface registered on nine skills in this order: SearchQA, LiveMath, CommonsenseQA, OpenBookQA, ARC, SciQ, QASC, BoolQ, GPQA.

Path 2, reward learning (§3.5, App. A.3).
- One compact factor pair, 32 slots x 256 dims (16,384 parameters), read at every depth, plus a new task interface (1.31M parameters, Table 18). Backbone frozen. No skill text in the prompt.
- For each prompt sample 8 responses at temperature 1.0, score with the task verifier, normalize reward within the group (Eq. 13), skip groups with constant reward. 300 steps, 8 prompts per step. AdamW, weight decay 0, clip each tensor to Frobenius norm 1.0, truncated importance ratio capped at 2.0.
- Two starts: "RL from scratch" (empty) and "RL from skill" (a "compact text-informed initialization", not described further).

Rank cut (§4.2, App. C.2). After registration, SVD each operator, keep rank k, scale by c_k = (k/N_s)^(1/4). Interface fixed.

Baselines (App. B.3). Base. Text Skill (seed skill in the prompt). SkillOpt (an outside optimizer edits the skill text from scored rollouts and keeps an edit only if it passes a validation gate). SoftSkill (32-vector soft prefix trained with cross-entropy on the gold answer). In Table 5: soft prefix, prefix KV, LoRA, bias-only steering, all trained with the same reward recipe.

Missing for a clean reproduction: layer indices, the gate's form, Omega, the "universal skills" pre-training, the text-informed initialization, and what data the behavior-cloning control clones.

## Setting, data, models

- Backbones: Qwen3.5-4B, Qwen3.6-35B-A3B, GLM-4.7-Flash, gpt-oss-20b (App. B.2). Thinking is off on Qwen and GLM. gpt-oss-20b runs at lowest reasoning effort for registered runs and template default for reward-learned runs, so those two rows are not decoded the same way.
- Registration is run only on Qwen3.5-4B and gpt-oss-20b. The full substrate comparison (Table 5) is only on the two Qwen models.
- Ten benchmarks. LiveMath (124 test), SearchQA (1,400), DocVQA (374), CommonsenseQA (1,221), OpenBookQA (500), STaRK-Prime (500), STaRK-MAG (497), OfficeQA (172), SpreadsheetBench (280), ALFWorld (134) (App. B.1).
- Split 2:1:7 train/selection/test, seed 42. Registered KV-Skill rows are scored on seeded subsets (SearchQA 300, CSQA and OBQA 200, all 124 LiveMath). Baseline rows are on the full test split. So the rows in Table 1 are not always on the same items.
- The registered SearchQA and LiveMath operators come from SkillOpt's "GPT-5.5-optimized skill" (App. B.4). Other rows use the seed skill.
- On GLM and gpt-oss, SkillOpt and SoftSkill were rerun with their own decoding settings (temperature 0.7 and 8,000 tokens for SkillOpt; greedy with 16 or 64 new tokens for SoftSkill). These differ from the KV-Skill settings.

## Metrics (exact definitions)

- LiveMath, CSQA, OBQA: multiple-choice accuracy.
- SearchQA: exact match. STaRK: exact match on a ten-candidate selection version of the task.
- DocVQA: ANLS (average normalized Levenshtein similarity).
- OfficeQA, SpreadsheetBench, ALFWorld: task success rate.
- A response is scored up to its first `</answer>` tag. With no tag, the last line is scored.
- KV-Skill rows are mean ± s.d. over three seeds. Baseline rows are single numbers. Rank analysis (Table 4, 9, 10) is one seed.

## Results, including weak and negative ones

Main (Tables 1, 3), gain over Base on LiveMath:
- Seed text skill: +0.8 (4B), -4.8 (35B), +4.0 (GLM), +0.1 (gpt-oss). Plain text does about nothing.
- SkillOpt text: +19.7, +7.7, +21.7, +1.7.
- KV-Skill RL from scratch: +43.3, +38.7, +52.4, +30.1.
- Registered: +44.9 (4B), +42.8 (gpt-oss).

SearchQA gains are smaller: registered 79.3 vs text 71.2 on 4B. On gpt-oss-20b SearchQA the optimized text (74.9) matches the reward-learned operators (74.2, 75.5).

Weak and negative results:
- Registered operator hurts general QA on gpt-oss-20b. CSQA 71.8 vs Base 81.6. OBQA 82.3 vs Base 94.6 (Table 3). The paper does not discuss this. On Qwen3.5-4B it is slightly below Base too (79.3 vs 80.7, 88.7 vs 90.6).
- Long-horizon agent task. ALFWorld: SkillOpt text 81.3, behavior cloning 69.4, KV-Skill RL 40.3 to 42.3, Base 30.6 (Table 16, App. C.6). Text wins by about 39 points. The authors blame sparse reward.
- SpreadsheetBench: RL from scratch 22.3 is below SkillOpt text 23.9. Only RL from skill (25.8) is above. The main text says reward learning "beats SkillOpt" there.
- Several trained forms end below Base on LiveMath: prefix KV with RL 16.1 (4B, Base 32.3); soft prefix with RL 28.8 and 26.3 (35B, Base 33.9) (Table 5).
- Behavior cloning: every substrate lands at 17.7 to 24.2 on 4B LiveMath, under Base 32.3. The text calls this "no gain". On 35B the same control helps (KV-Skill 57.3, LoRA 62.9), and LoRA beats KV-Skill (Table 12).
- Junk in the prompt hurts. Same-length random tokens with no operator: LiveMath 13.7 vs 32.3 (Table 2).
- A random operator through the registered interface hurts: 25.4 vs 32.3 on LiveMath, 61.3 vs 68.1 on SearchQA (Table 6).
- The interface alone carries part of the SearchQA gain. No operator 71.7, wrong-task operator 71.0 to 73.1, correct 77.3 to 79.3, Base 68.1 (Tables 6, 11). My arithmetic: about half of the SearchQA gain is operator-specific. On LiveMath about 90% is.
- "RL from skill" vs "RL from scratch" differ by less than one s.d. almost everywhere.
- Sharing the interface costs LiveMath 3.5 points (73.4 vs 76.9, Table 14).
- Capacity does not matter. One slot gives 77.9 on SearchQA, 32 slots 80.0, 128 slots 77.4 (Table 13, single runs).

## Limitations

Theirs (§6): extra compute per injection depth; one interface per backbone; text-derived operators are backbone-specific and large before compression; swapping mid-conversation may need a re-prefill; most analysis is on Qwen3.5-4B and QA tasks; long-horizon agent evidence is thin; no cross-backbone transfer test. App. D.7 says plainly it is not uniformly cheaper inference.

Mine:
- LiveMath carries the headline. It has 124 test items and about 35 training items. The authors call it a "threshold task" where one test-taking procedure (pick the strongest justified option) flips the score. The 25-point gap may not carry to tasks without such a switch. On SearchQA the gap is 8 points and on general QA it is zero or negative.
- "Same document as text" is not fully pinned down. The operator is built from SkillOpt's "GPT-5.5-optimized skill". The 52.0 text row is SkillOpt on Qwen3.5-4B. The paper says these are the same document but does not show it. On gpt-oss-20b the text row was rerun with different decoding.
- Registered rows and baseline rows use different test subsets and different numbers of seeds.
- Registration uses gold labels and a text-reading teacher. The text baseline it beats most cleanly (seed Text Skill) uses no labels. The fair comparisons are SkillOpt and SoftSkill, which the paper does state.
- For reward-learned KV-Skills the trained interface (1.31M parameters) is 80 times larger than the operator (16K). The swap test that shows "the task lives in the operator" was run only for registered operators. For the reward-learned ones the knowledge may sit in the interface.
- Token counts and slot counts do not line up (LiveMath skill 671 tokens, SearchQA 2,035, but "full rank is 512" for both). Not explained.
- The single-skill LiveMath baseline selects its checkpoint on the test split (App. B.1).
- No build cost. Registration and 19,200 rollouts per reward-learned skill are not costed.
- Needs weight access. It cannot be used on API-only students.

## Untested assumptions

- That the gain reflects better use of procedural knowledge and not a learned answer-format or option-picking bias. The wrong-task control helps, but it is one task pair.
- That four mid-size open models stand in for a capability range. Their LiveMath Base scores are all between 18.6 and 33.9.
- That results from single-turn QA carry to multi-step agents. Their own ALFWorld number says no.
- That a skill written or optimized for one model is the right source text for another.
- That aggregate accuracy hides no per-item harm. No pass-to-fail counts are given.

## Overlap with Loopy (K1 to K6)

- K1, text vs executable from the same failure, teacher and student: **not covered**. There is no code or tool form, no teacher, and no artifact built from a failure. What it does cover is the neighboring comparison: one document as prompt text vs latent operator vs soft prefix on the same frozen model (Tables 1, 2, 3).
- K2, student-capability axis by form: **partly**. Four backbones, and Table 5 compares five forms on two Qwen sizes. The backbones are not ordered by strength and no interaction is tested. Raw material only: under matched reward training on LiveMath the soft prefix falls from 59.7 (4B) to 28.8 (35B) and LoRA from 78.6 to 52.7 while KV-Skill holds (75.6, 72.6). Behavior cloning hurts the 4B model and helps the 35B (Table 12).
- K3, task-difficulty axis: **not covered**. Only differences between benchmarks. The nearest signal: on long-horizon ALFWorld the text form wins and the latent form fails (Table 16).
- K4, non-text help that harms a capable student: **partly**. Aggregate drops below Base for non-text forms exist (gpt-oss-20b CSQA -9.8 and OBQA -12.3 with the registered operator, Table 3; prefix KV 16.1 vs 32.3, Table 5). They are not per task, not discussed as harm, and not tied to student strength.
- K5, controls: **partly**. Strong placebo controls for its own forms: random tokens (Table 2), random and wrong-task operator (Table 6), random direction (Table 4), seed vs optimized source (Table 10). No generic note vs tailored note. The keep-only-if-it-passes gate exists only inside the SkillOpt baseline. Standard i.i.d. splits, no variants of a repeating task.
- K6, cost and break-even: **partly**. App. D gives per-use cost of text (tokens, FLOPs) against the operator, storage and latency. It gives no build cost, no failed builds and no number of uses to break even. It also shows that with prefix caching the text costs about the same at first token (Table 20).

Plain answers:
- Does it compare knowledge forms on the same students? Yes: prompt text (seed and optimized), soft prefix, prefix KV, latent operator, LoRA, bias steering. No executable form.
- How many students, what strength? Four frozen open models of 4B to 35B parameters with similar Base scores. Not a weak-to-strong ladder. The full form comparison is on two.
- Does any form help weak models more than strong ones, or the reverse? Not analyzed. In the tables: optimized text helps the 4B more than the 35B on LiveMath (+19.7 vs +7.7) and less on SearchQA (+3.1 vs +7.6). Behavior-cloned forms help the larger model and hurt the smaller on LiveMath.
- Any case where a form hurts? Yes, see the weak and negative results: registered operator on gpt-oss-20b general QA, prefix forms and behavior cloning on LiveMath, seed text on the 35B model (-4.8), random tokens.

## What we can no longer claim

- That we are first to show the same knowledge gives a different benefit depending on its form, with the student held fixed. This paper shows it for text vs latent operator (52.0 vs 77.2).
- That "a small model can hold a correct procedure in its prompt and still fail to execute it" is our observation. It is this paper's opening argument (§1) with data behind it.
- That a generic or unoptimized text skill doing almost nothing for a small model is new. Seed Text Skill is within a few points of Base on all four backbones (Tables 1, 3, 8). Our 11% generic-note number fits that.
- That nobody has counted the per-use cost of a text skill against a compiled form. App. D does, without a break-even.

## What stays open

- Text vs an executable function, built from the same failure by the same teacher for the same student. Not here.
- Whether the best form changes with student strength, tested on purpose. Not here.
- Any difficulty axis inside one task family.
- Per-task harm counts: tasks a student passed alone and then failed with help.
- Variants of a repeating task, a generic-note placebo, and a keep-if-pass gate applied to every form.
- Build cost, failed builds and break-even.
- API-only students. KV-Skill needs weights. A function or a note does not.
- Reading this paper next to SKILL-KD (2607.28048), which uses the same two Qwen students and five of the same benchmarks: text distilled from a teacher wins on ALFWorld (86.6 vs 42.3 here), the latent form wins on LiveMath and DocVQA, and they tie on SearchQA and SpreadsheetBench. The two papers disagree on the LiveMath Base for Qwen3.5-4B (22.4 there, 32.3 here), so this is a lead, not a result. It suggests the best form depends on task type. Neither paper tests code.
