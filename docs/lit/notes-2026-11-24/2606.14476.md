# 2606.14476 v1 (12 Jun 2026). Wang and Vemuri, raptorX.ai. "When the Tool Decides"

Venue framing: written for TMLR (Sec 1, "Who should care"). Single version, 9 pages including appendix. Code and results JSON said to be released (Sec 10), no URL in the paper.

## Claim

- A ReAct agent given a frozen GCN as a tool copies the GCN's label. Prediction agreement with the raw GCN is 0.976 to 0.992 across three homophily bins at Qwen2.5-7B (Table 1, Sec 4).
- The same agent's tool-using answer matches its own tool-free answer only 17 to 37% of the time at 7B, 7 to 20% at 3B (Sec 4, Contributions bullet 1).
- In 83% of 7B queries the agent makes exactly one tool call and never calls the anomaly tool that is described to it as "higher means the GNN is more likely wrong" (Sec 4, App A).
- Agreement rises with backbone size among models that can use the tool: 0.60 (1.5B), 0.97 (3B), 0.98 (7B), 5 seeds (Table 2, Fig 2, Sec 5).
- The cost of deference (per-node oracle gap) does not shrink from 3B to 7B and doubles in the high-homophily bin, 0.12 to 0.22, paired t = 9.1, positive in 5 of 5 seeds (Table 3, Sec 6).
- A post-hoc purity gate fixes the high bin (0.71 to 0.83) but hurts the others, net 0.481 to 0.475 (Sec 7). A held-out "best gate" over four standard features recovers only one sixth to one third of the oracle headroom (Sec 7).
- Replicated on WikiCS at 7B, 3 seeds: agreement 0.96 to 1.00 (Table 4, Sec 8).
- Boundary: Mistral-7B and OLMo-2-7B under an English scaffold agree only 0.53 and 0.60, so near-total parroting is partly Qwen-specific (Sec 9).

## Method in enough detail to reproduce

- Task: node classification, one query node at a time. Prompt gives the node's title plus abstract (truncated to 500 characters) and the candidate class list (App A).
- Tool model: 2-layer GCN, hidden size 128, with a reconstruction head. Trained 200 epochs on the official training split, best-validation checkpoint, then frozen. Retrained per seed (App A).
- Four arms under a matched budget of 5,000 prompt plus generation tokens and 6 tool calls per query (Sec 3):
  - A1: agent plus GNN tool. Three calls bound to the query node: `gnn_predict()` returns "class=c conf=p"; `gnn_anomaly()` returns a reconstruction anomaly score, described as "higher means the GNN is more likely wrong on this node"; `gnn_link(neighbour-id)` returns a link probability.
  - A2: agent plus navigation tool. `neighbors()` returns up to 10 neighbour ids with their training labels ("?" if not in train, no text); `degree()`.
  - A3: frozen GNN alone (charged one call).
  - A4: agent with no tool, node text only. System prompt: output one line "ANSWER: <class id>".
- Agent loop: text-protocol ReAct, regex-parsed ACTION/ANSWER lines, at most 4 steps, each tool observation fed back as a user turn. On budget exhaustion or after the last step, a forced "ANSWER:" turn. If no in-range class id is found, fallback to class 0 (App A).
- System prompt for A1/A2 (translated from Chinese): "You are a classification agent; call tools to gather evidence first, then answer." So tool invocation is instructed. All scaffold text is in Chinese; node text in English (Sec 3, App A).
- Decoding: temperature 0.7, top-p 0.9, max 256 new tokens per turn. Seeds fix GNN training and node sample, not LLM decoding. vLLM for Qwen 1.5B to 7B, HF transformers for 0.5B and Mistral (App A).
- Sampling: test nodes stratified by local homophily (fraction of same-label neighbours, using ground truth) into low (<0.3), mid [0.3, 0.7), high (>=0.7). 50 nodes per bin, 5 seeds, so 750 nodes per backbone. Homophily is never given to the agent (Sec 3).
- Gate (Sec 7): route a node to A2 when the training-label purity of its neighbourhood exceeds tau = 0.4 (picked on seed 0), else A1.
- Learned router (Sec 7): four features (purity, GNN confidence, degree, neighbour disagreement), routes to {GNN, A2, A4}, leave-one-seed-out over the 750 nodes.
- Ceiling estimate (Sec 7): leave-one-seed-out kNN best-arm policy (k = 31, standardized features) and a median-binned cell policy, each compared to a feature-shuffled null.

## Setting, data, models

- ogbn-arxiv: 169k nodes, 40 classes, title plus abstract text (Sec 3).
- WikiCS: 11.7k nodes, 10 classes, edge homophily 0.66; 7B only, 3 seeds, 40 nodes per bin (Sec 8).
- Backbones: Qwen2.5-Instruct 0.5B, 1.5B, 3B, 7B. Cross-family probe: Mistral-7B-Instruct, OLMo-2-7B-Instruct (Sec 9). No closed models, nothing above 7B (single-GPU constraint, Sec 9).

## Metrics (exact definitions)

- Accuracy per arm.
- Deference ("parrot") = agreement = Pr[A1 pred = A3 pred], prediction level, per bin (Sec 3). Not chance-corrected. Counts all agreement, including nodes where the agent would have picked the same label anyway.
- Cost of deference = oracle gap = acc(max{A1, A2, A4}) minus acc(A1), where the max is per node (a node counts as correct for the oracle if any of A1, A2, A4 got it right). Non-negative by construction (Sec 3).
- Tool-call count: mean calls per query, reported for the low bin only (Table 2).
- Reported as mean plus or minus SE over seeds.

## Results, including weak and negative ones

- 7B arxiv (Table 1): A1 tracks A3 exactly per bin (0.29 vs 0.30, 0.44 vs 0.44, 0.71 vs 0.71). A4 no-tool is far lower (0.16, 0.20, 0.42). A2 beats the GNN only at high homophily (0.81 vs 0.71) and loses badly at low (0.13 vs 0.30).
- Capability sweep (Table 2): 0.5B agreement 0.10 / 0.00 / 0.10 with 0.30 calls; this is incapacity, and its answers often come from the class-0 fallback. 1.5B 0.62 / 0.60 / 0.58 with 1.23 calls. 3B 0.98 / 0.96 / 0.98, 1.00 calls. 7B 0.98 / 0.98 / 0.99, 1.07 calls. The 0.5B row and the calls column are seed 0 only, 30 nodes per bin.
- Weak point the authors admit: the agreement trend saturates at 3B; 3B to 7B (0.97 to 0.98) is within noise, so the load-bearing contrast is 1.5B versus 3B and up (Sec 9). No significance test is reported for the agreement trend itself.
- Oracle gap (Table 3): 1.5B 0.048 / 0.168 / 0.228; 3B 0.092 / 0.184 / 0.120; 7B 0.120 / 0.184 / 0.220. Only the high bin grows significantly (t = 9.1, survives Bonferroni over 3 bins). Low: 4 of 5 seeds, t = 0.8, not significant. Mid: unchanged, t = 0.0.
- 1.5B: A1 trails the GNN by 0.12 to 0.28, so its deviations from the tool cost accuracy (Sec 6). A partially deferring weak agent does worse than the tool alone.
- A4 tool-free rises from at most 0.10 at 1.5B to 0.16 to 0.42 at 7B (Sec 6).
- Gate (Sec 7): high 0.71 to 0.83 (oracle 0.93, paired t = 4.0, 5 of 5 seeds), low 0.29 to 0.18, mid 0.44 to 0.41, global 0.481 to 0.475. A seed-0-only run had shown +0.07; it did not survive 5 seeds (a negative result they report openly).
- Learned router 0.496 plus or minus 0.026 vs validation-picked purity gate 0.499 plus or minus 0.016 vs parrot 0.481 plus or minus 0.026; oracle 0.656 plus or minus 0.024. An earlier iid single split: 0.527 vs 0.533, oracle 0.647.
- Ceiling: kNN 0.537 plus or minus 0.025, cell 0.508 plus or minus 0.021; nulls 0.469 and 0.472. Recoverable share of the 0.175 headroom is 0.027 to 0.056 (Sec 7). WikiCS: 0.014 to 0.017 of 0.119 headroom, about 12 to 14%, clears null "by a small margin" (Sec 8).
- WikiCS (Table 4): parrot 0.25 / 0.75 / 0.96, nbr-label 0.38 / 0.68 / 0.85, gap 0.23 / 0.10 / 0.03, agreement 0.98 / 0.96 / 1.00. The gap peaks at low homophily here, not high. GNN-alone and no-tool columns are not shown for WikiCS.
- Cross-family (Sec 9): Chinese scaffold, Mistral called the tool 0.39 times (n = 40), agreement 0.20. English scaffold, 3 seeds, 60 nodes, shared GNN: Mistral 1.27 calls, agreement 0.53 plus or minus 0.01, A1 0.32; OLMo 1.39 calls, 0.60 plus or minus 0.03, A1 0.36; shared GNN 0.49. Qwen-7B in English still 0.978 plus or minus 0.015. Non-Qwen agents deviate from the tool and lose accuracy by doing so.

## Limitations

Theirs (Sec 9):
- One task type (node classification), two graphs, Qwen2.5 family, one GCN tool. Magnitudes not claimed to transfer.
- Nothing above 7B.
- Capability trend is observational; no mechanism isolated.
- Gates do not close the gap globally.
- Near-total parroting is partly Qwen-specific.
- Heterophilous graphs left for future work.

Mine:
- The prompt tells the agent to call tools first. Deference is measured under an instruction to consult, with no condition that tells the agent to verify or weigh evidence.
- Agreement is not chance-corrected and no A3 vs A4 base-rate agreement is reported, so part of the 0.98 could be agreement the agent would reach anyway. Small in practice, since A1 vs A4 agreement is only 0.17 to 0.37.
- "Stronger" is parameter count within one family. Four points, of which 0.5B is non-functional, and 3B vs 7B is flat. Effectively the trend is one contrast, 1.5B vs 3B. At 7B, other families defer much less, so size and family are confounded.
- The 1.5B agent's lower agreement may be format or reasoning failure rather than skepticism (its deviations are wrong). "Defers more" may partly mean "follows the tool protocol more reliably".
- The oracle is a max over three arms with sampled decoding at temperature 0.7. On a 40-class task, a per-node max over noisy predictors gains from chance alone. The oracle gap is an optimistic upper bound on what judgment could recover, and the ceiling analysis in Sec 7 implicitly shows this (most of the gap is not recoverable).
- The anomaly tool's own quality (does it actually flag GNN errors?) is never reported, so "never probes the signal designed to flag errors" does not show that probing would have helped.
- Tool reliability is never varied. We cannot tell whether deference tracks how good the tool is.
- Small n: 50 nodes per bin, 5 seeds. Mixed-provenance Table 2.
- No per-item comparison of A1 against A4 (agent alone). The paper cannot say on how many nodes the tool made the agent wrong where it was right alone.
- Single-shot classification, at most 4 ReAct steps. Not a multi-step task with an executable environment.

## Untested assumptions

- That agreement under a "consult tools first" instruction reflects the agent's judgment rather than instruction following.
- That the oracle gap measures cost of deference rather than decoding noise plus complementarity.
- That parameter count is the right axis for "capability".
- That the anomaly score is informative.
- That the result generalizes from a single classifier output to tools that return procedures or multi-step results.
- That A4's poor accuracy (0.16 to 0.42) reflects agent ability rather than the short 500-character text and 40-way label list.

## Overlap with Loopy

- **M1, agents adopt a tool's output without checking: COVERED.** Defined as Pr[A1 pred = A3 pred] (Sec 3). 0.976 to 0.992 at 7B (Table 1). 83% of 7B queries make exactly one call and skip the anomaly check (Sec 4). Same shape as Loopy's "call once and stop" pattern. Difference: their "check" is calling a second tool; Loopy's check is inspecting the function's result in an environment.
- **M2, deference vs backbone strength: COVERED, with caveats.** Qwen2.5 0.5B / 1.5B / 3B / 7B; strength = parameter count; 4 models; agreement 0.07 (incapacity), 0.60, 0.97, 0.98 (Table 2, Fig 2). Monotone among 1.5B and up, saturates at 3B, 3B vs 7B within noise. No statistical test on agreement; the paired t-test (t = 9.1) is on the oracle gap at high homophily only. Cross-family 7B: Mistral 0.53, OLMo 0.60 (Sec 9). Loopy's finding (call-once rate about the same for every student) is closer to their 3B vs 7B plateau than to their headline rise.
- **M3, deference makes a capable agent worse than alone on items it solves unaided: PARTLY.** They measure a cost via the per-node oracle over {A1, A2, A4} (Table 3), and A4 is in that set. But they never split out nodes where A4 was right and A1 wrong, so no "broke X of Y it passed alone" number exists. On average the tool helps a lot over no-tool (7B: A1 0.29 / 0.44 / 0.71 vs A4 0.16 / 0.20 / 0.42, Table 1), so the per-item harm is unquantified and the aggregate effect is positive. Loopy's 7 of 86 regression count on strong students is not covered.
- **M4, teacher-built, task-specific function: NOT.** The tool is a frozen GCN trained on the dataset's training split. It is task-trained but fixed, returns a label, and is not built from the agent's failures or by a stronger model.
- **M5, text advice vs callable tool with the same content: NOT.** No text-advice arm. A2 is a different tool (neighbour labels) and A4 is no tool.
- **M6, mitigation: COVERED for a gate, and it failed globally.** Post-hoc purity gate outside the agent: high bin 0.71 to 0.83, low 0.29 to 0.18, mid 0.44 to 0.41, global 0.481 to 0.475. Learned router 0.496 vs parrot 0.481, oracle 0.656. Held-out ceiling recovers 0.027 to 0.056 of 0.175 (Sec 7). No prompt-level mitigation (for example "verify the tool result"), no in-agent mitigation, no training.

**Substitution question: do weak and strong backbones end at the tool's accuracy?** Yes for the two full-parrot models, no for the weak one. At 3B and 7B, A1 sits within plus or minus 0.02 of A3 per bin (Sec 6; 7B: 0.29 / 0.44 / 0.71 vs GNN 0.30 / 0.44 / 0.71, Table 1), while their tool-free accuracy differs (A4 at 7B is 0.16 to 0.42; 3B per-bin A4 is not tabulated). That is the substitution pattern: tool-on accuracy equals the tool's accuracy, independent of the agent's own ability. The 1.5B agent ends below the tool (A1 trails GNN by 0.12 to 0.28), and Mistral and OLMo also end below (0.32 and 0.36 vs 0.49). So in this paper, weaker or less deferent agents land under the tool's accuracy, not on it. Loopy's pattern (every student lands about the same, about 91%) matches their 3B and 7B, not their 1.5B.

## What we can no longer claim

- That "agents call a tool once and adopt its output without checking" is a new observation. This paper shows it, with a definition, for a learned predictor tool.
- That "tool-on accuracy pins to the tool's own accuracy regardless of the agent's own ability" is new in general. Table 1 and Sec 6 show this for 3B and 7B Qwen.
- That "stronger models do not become more skeptical of tools" is new. They report it (Sec 5), though their evidence is one step and one family.
- That deference forgoes better options a capable agent had. Their oracle gap makes this point (Sec 6).

## What stays open

- A teacher-built executable function made from the student's own failure (M4).
- Note vs function with the same content, and whether a note amplifies ability while a function substitutes for it (M5). This paper has no amplification arm at all.
- A per-item regression count against a no-tool baseline on tasks the agent solves alone (M3). Their oracle gap does not give it.
- Multi-step, environment-executed tasks where the agent can check the result (AppWorld). Their task is single-label classification.
- Whether deference tracks tool reliability, since they never vary the tool's quality.
- Prompt-level or in-agent mitigation (ask the student to verify the function's output). Their only mitigations are external gates.
- The near-flat deference across student strength in Loopy vs their rising curve. Their own data (3B vs 7B flat, cross-family 0.53 to 0.60) suggests deference depends on family and protocol, not on strength alone.
