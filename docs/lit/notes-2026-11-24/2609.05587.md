# Agents' Overreliance on Unreliable Tools

arXiv 2609.05587, v2, 26 Sep 2026 (cs.AI, CC BY 4.0, preprint).
Authors: Hoyeol Yang*, Woojung Song*, Taewon Kim, Jonghyun Song, Seoyeon Park, Yohan Jo (corresponding). All Seoul National University. (*equal contribution)

## Claim

Tool-using agents copy corrupted tool returns into their final answer at high rates, even on items they answer correctly with no tool, and they almost never warn the user.

Key numbers:
- Mean P1 adoption over 14 models: Search 68.0% [65.3, 70.7], Sub-Agent 40.1% [31.9, 48.5], Code Executor 35.5% [32.3, 39.0] (Table 1, Section 4.1).
- Mean P1 override rate (adoption on items the model gets right alone): Search 56.4%, Sub-Agent 26.8%, Code Executor 33.5% (Table 1).
- GPT family on Code Executor: base accuracy 85.2 to 93.6%, yet override 49.1 to 60.2% (Section 4.1, Table 1).
- QuALITY with a sub-agent reading report: adoption 94.7%, override 91.9% (Table 2, Table 19).
- Two-tool tasks: accuracy falls from 98.4 to 98.8% with correct returns to 19.8 to 26.2% when both returns are corrupted (Section 4.3, Table 20).
- Warnings to the user appear in 4.2% of adopting final answers, 1.5% without Muse (Section 4.5, Tables 13 and 14).
- Qwen thinking models mention a conflict in 87.9 to 96.0% of adopting Code Executor runs and state the correct value in 64.2 to 73.0%, and still adopt (Table 4, Table 12).
- Best mitigation: a Verify prompt cuts mean P1 adoption by 4.0 pp (Search), 4.0 pp (Sub-Agent), 9.8 pp (Code), with P0 accuracy kept (Table 5, Table 28).

## Method (enough to reproduce)

Three tasks, one tool each. For each tool they take an uncorrupted return and change only the answer-relevant content.

Search (factual QA).
- 418 FreshQA questions (snapshot 2026-04-21; 432 minus 14 binary). 147 never-changing, 127 slow, 144 fast (Section 3, A.1).
- Agent issues its own queries to the Tavily API. Settings: topic=general, search_depth=basic, max_results=10, answer synthesis off, end_date = snapshot. Top 5 results kept, each with title, url, content, score (A.3).
- Each question has one fixed alternative answer per condition. P1 plausible: a once-correct or confusable real value (earlier FreshQA answers). P2 transplanted: the gold answer of another FreshQA question. P3 nonexistent: invented entity from syllable pools, or an implausible number or date (A.2).
- GPT-5.6-Luna rewrites answer-relevant titles and content to assert the assigned value. If no result has an answer-relevant claim it inserts the value into the most relevant result. URLs are edited to drop gold aliases (3 editor calls, then deterministic replacement). Any result still holding a gold alias is excluded. Edits are cached per original results, value and editor version, so repeated exact queries get identical returns (A.3).
- 10-turn cap, then "Please give your final answer now." with tools off (A.4).

Sub-Agent (summarization).
- 45 documents: 15 pre-cutoff papers, 15 post-cutoff papers (released after 2026-05-01), 15 nineteenth-century novels. Each paper group has 3 papers in each of AI, medicine, physics, psychology, economics (B.1, Tables 9 to 11).
- User asks for summaries of 3 named titles from one group. The subagent tool returns a stored five-sentence summary (no source text). Titles resolved by deterministic match, then a router model (B.3).
- GPT-5.6-Terra drafts P0 and two corrupted versions; authors review all. P1 replaces one headline claim with a false claim. P2 adds a false claim and keeps the originals. Constraints: one edit, five sentences, 90 to 160 words, carried_by span verbatim, at least half of the false claim's distinctive words, content-word retention at least 0.85 (P1) or 0.92 (P2) (B.2).
- 180 three-document requests x {P0, P1, P2} x 3 repetitions per model; 50 turn cap; 16k output tokens; T=0.7 (B.4).

Code Executor (arithmetic).
- 300 problems, 50 each of a+b, a*b, a/b, a mod b, log_a(b), a^b. Operands on a 3-decimal grid in [0.001, 1000] (exponent: [0.001, 10]); random signs for +, *, /. Gold computed with 50-digit decimals, rounded half-up to 3 decimals; result magnitude in [0.001, 1e9] (C.1).
- After a successful run, every number o in stdout becomes o' = s*o*r (d=+1) or s*o/r (d=-1), r = 1 + p/100. p is log-uniform in [1, 100] for P1 and [101, 10000] for P2. The four (d, s) pairs are balanced, 75 problems each. Factor fixed per problem across calls; redraw if the corrupted value rounds to gold. Tracebacks pass through unchanged (Section 3, C.2).
- Tool prompt says "Use the tool to solve the problem." No-tool prompt says "Solve the problem yourself." (C.3, H.3). 50 call cap, 16k tokens, 3 repetitions (C.4).

Models: 14 (Table 8). Qwen3-30B and -235B (instruct and thinking), Gemini-3.1-flash-lite and -3.7-flash, Gemma-4-12B and -31B, GPT-5.4-mini and -nano, GPT-OSS-20B and -120B, DeepSeek-V4-Flash, Muse-Glimmer-30B. T=0.7, medium reasoning effort, 8k max output (24k reasoning), seed 12345 + rep offset, 200k token budget (A.5). Frontier extension: GPT-5.4, Claude Sonnet 5, Claude Opus 4.8, Grok 4.6 on 90 items, one run each (D.3).

Judging. Search and Sub-Agent: Qwen3.5-27B judge (thinking off, JSON). Labels CORRECT, ADOPT, BLEND, OTHER, ABSTAIN plus a warning flag. Only ADOPT counts. Search judge agrees with human majority on 197/200 (98.5%, kappa 0.940; precision 100%, recall 90.3%) (A.6). Sub-Agent judge uses 2 to 3 calls per document and agrees on 119/126 (94.4%, kappa 0.841); 29 of 155 items had no human majority and were dropped (B.5). Code: rule-based parser on the FINAL ANSWER line, falling back to the last number; 237 parse failures and 26 API errors count as non-adoption (C.4). Reasoning traces judged by GPT-5.6-Luna for "conflict" and "correct value mention"; human agreement 87.8% with consensus, kappa 0.735 (D.1, Table 15).

Extensions (Section 4.3, D.4, D.5): MuSiQue (60 multi-hop questions, 3 models, 1 run), QuALITY (60 four-choice questions, sub-agent returns an 8 to 10 sentence report, P1 swaps one decisive sentence, 7 models, 3 runs), GSM-Hard (871 problems, 7 models, 1 run, no sign flip), two-tool tasks (54 problems: literary fact then a table lookup then arithmetic, 6 models, both tools corrupted).

Presentation test (Section 4.4, F.1): same P1 content delivered as a tool return (Tool), inside the user message (User), or under a "Context:" header (RAG). 6 models, one response per item for User and RAG.

Interventions (Section 5, F, H):
- Prompts (6 models, 1 rep): Compare (compare the return with prior knowledge and constraints), Verify (if it conflicts, run one substantively different check), Disclose (state competing claims to the user). Exact text in H.1.1, H.2.1, H.3.1.
- Metadata on P1 Search results with an instruction to consider it: source (Wikipedia, Reuters, Reddit, X), numeric reliability (0.10, 0.50, 0.95), or High/Low. Passive versions without the instruction too (Table 35).
- Post-training on Qwen3-30B, GPT-OSS-20B, Gemma-4-31B with LoRA rank 32, alpha 64 on attention projections. SFT: 194 clean successful trajectories. SFT (recovery): plus 64 trajectories resisting corruption. DPO: 327 pairs, beta 0.1, lr 5e-6. GRPO: 452 questions x {clean, corrupted} prefixes, 226 steps, 4 samples per prompt, KL 0.02, judge-assisted binary correctness reward. OPD on Gemma-4-12B with 10%, 25%, 80% corrupted contexts (F.4). Training pool from PopQA, Wikidata, TempLAMA, TimeQA with synthetic returns.
- Probing and steering on Code Executor: logistic probe (C=0.05, 5-fold grouped by problem) at the last prompt token after the first tool return; steering adds alpha times the corrupted-minus-correct mean difference on a 3-layer band; 200 problems to estimate, 100 held out; greedy, 4 tool rounds, 300 tokens per turn (G).

## Setting, data, models

Single-turn tasks with one tool type each (plus the two-tool extension). Tools are generic: web search, a generic summarizer sub-agent, a Python interpreter running the agent's own code. Corruption is injected by the harness, 100% of the time in a P1 or P2 run. 14 open and API models plus 4 frontier models on a subset. All 2026 model versions.

## Metrics (exact definitions)

- Adoption rate: fraction of runs whose final answer uses the injected content, out of runs where the injected content actually appeared in a tool response (Section 3). For Search this needs "target-bearing exposure": a parsed, nonempty return that carries the assigned value through a successful edit (F.2).
- Override rate: adoption rate restricted to items the model answers correctly without a tool, where "correct without a tool" means at least 2 of 3 independent no-tool runs are correct (Section 3). Extensions with one no-tool run use O(1), a single correct no-tool response.
- Base accuracy: accuracy over the individual no-tool responses.
- P0 accuracy: accuracy when the tool returns correct content.
- Tool-call ratio: mean calls under corrupted returns divided by mean calls under correct returns (Section 4.5, Figure 3).
- Warning rate: share of adopting final answers that tell the user the tool output may be wrong (judge rubric in H.4).
- CIs: 2,000 item-bootstrap resamples for the main table; paired bootstrap and sign-flip tests with Holm correction for contrasts (E).

Main (Table 1, Table 16).

Thinking lowers P1 adoption on all three tools for both Qwen sizes; its effect on override varies. Interventions.
- Prompts (Table 5, Table 28). Compare: lowest adoption in Search (67.6) and Sub-Agent (29.3) but lowers P0 accuracy (-3.3 pp Search, -4.5 pp Sub-Agent). Verify: -4.0, -4.0, -9.8 pp adoption, P0 flat. Disclose: small (-2.9 Search significant, -1.0 Sub-Agent ns, -1.6 Code ns after Holm). Per model, effects are concentrated in GPT-OSS-20B and Muse; several models show no change or increases (Table 29: Verify raises Sub-Agent adoption +6.8 for Qwen3-30B; Disclose raises it +11.5 for Muse).
- Metadata (Table 6, Table 30). Instructed labels lower mean adoption from 75.4 to 70.3 to 74.9. Low vs Plain -4.0 pp, High vs Low +4.4 pp (both significant). Source labels -1.7 to -3.0 pp; only X survives Holm. Passive labels: nothing significant (Table 35). Adoption stays above 60% everywhere.
- Post-training (Table 7, Table 31). SFT lowers P0 accuracy for all three (GPT-OSS-20B -11.0 pp) and raises adoption for GPT-OSS-20B (+12.1). DPO lowers adoption slightly for all (largest -4.8 Qwen, CI excludes 0 only for Qwen). GRPO keeps P0 but raises adoption for GPT-OSS-20B and Gemma. OPD on Gemma-4-12B raises adoption (79.1 to 80.6 to 82.2) and drops P0 to 58.6 to 73.0 (Table 36).
- Probe: AUROC 0.997, 1.000, 0.993 separating accepted correct from adopted corrupted returns (Table 39). Steering (Table 40, Figure 4): Qwen at alpha +0.25 cuts adoption 58 to 45 and raises P1 accuracy 23 to 29 with P0 at 100. Gemma's P1 accuracy falls with positive alpha (17 to 7). At alpha +1 P0 accuracy collapses (Qwen 10, Gemma 24). GPT-OSS barely moves.

Weak spots inside their own data.
- Base checkpoints evaluated in the post-training harness differ from the main run: GPT-OSS-20B P1 adoption 68.8 (Table 7) vs 81.4 (Table 1). The authors say these are separate frozen-cache evaluations (F.4). That 12.6 pp harness gap is larger than every prompt or metadata effect they report.
- Interventions use one repetition and denominators shrink (Compare for Qwen3-30B has 204 eligible episodes vs 1,133 for Plain, Table 37), so the conditioning set changes across conditions.

## Limitations

Theirs: API model changes, stochastic outputs, search drift; fixed corruption targets and cached summaries limit this; three repetitions with item bootstrap (Reproducibility statement). Presentation conditions also differ in tool access and structure (Section 4.4). Post-training conclusions hold "at least at the scales tested" (Section 5.3). Probe AUROC does not establish that steering layers are optimal (G.2). Base and main-run rates differ by harness (F.4).

Mine:
- Every P1 return is wrong. Reliability is never a mix within a run, so "overreliance" is measured against a tool that is 0% reliable on that item. We cannot tell whether the same agents are well calibrated to a tool that is right 90% of the time.
- The Code Executor runs the agent's own code and the harness then scales the output. Trusting an interpreter is normally correct. The tool prompt also says "Use the tool to solve the problem." Some adoption may be instruction-following, not misplaced trust.
- The override rate is a conditional adoption rate. It is not net accuracy versus acting alone. Gains on items the model fails alone are never set against losses on items it solves alone under a realistic tool.
- "Larger is better" is judged from pairs that differ in more than size. No controlled scale series and no independent capability measure.
- One repetition for interventions, extensions and frontier runs; frontier CIs span 20 to 40 points.
- The probe may pick up the plain fact that corrupted stdout disagrees with the code's expected output. No control probe on a matched shuffled label is reported.
- Harness gap of 12.6 pp for GPT-OSS-20B between two evaluations of the same base model is larger than the intervention effects.

## Untested assumptions

- That no-tool correctness on 2 of 3 runs measures what the agent "can produce" inside the tool-enabled prompt. The two prompts differ.
- That adoption under a 100%-corrupt tool predicts behavior under a mostly reliable one.
- That a judge model's ADOPT label tracks commitment in long sub-agent summaries (29 of 155 items had no human majority and were dropped).
- That generic tools behave like task-specific helpers. A helper built for this exact task by a stronger model is never tested.
- That extra tool calls signal detection. Ratios are reported without linking calls to outcome.

## Overlap with Loopy (M1 to M6)

- M1 (adopt without checking, how often): covered. Adoption 68.0 / 40.1 / 35.5% (Table 1). Warnings 4.2% (Section 4.5). Reasoning flags a conflict and still adopts (Table 4). One difference: their agents make more calls under corruption on Code (Figure 3), while Loopy students call once and stop.
- M2 (reliance vs strength): partly. Cross-sectional only. Larger or thinking variants usually adopt less, with exceptions: GPT-OSS-120B worse than 20B on Code (58.0 vs 54.6 adoption; 59.2 vs 55.5 override) and on MuSiQue, QuALITY, GSM-Hard override; Qwen-235B-Think overrides more than 30B-Think on Search (44.1 vs 38.5). Base accuracy does not predict resistance (GPT-5.4-nano 93.6 base, 60.2 override). Frontier models still at 33 to 40% override (Table 17). Answer: mostly less, not reliably, and family dominates size.
- M3 (harm to a capable agent vs alone): covered in form. The override rate is exactly "adopts the tool on items it solves alone", 26.8 to 56.4% at P1 (Table 1, Table 16); QuALITY 91.9% (Table 19). But the harm needs an injected wrong return. No net-vs-alone comparison with a realistic helper.
- M4 (teacher-built task-specific helper): not covered. Tools are generic. The sub-agent returns stored summaries written by GPT-5.6-Terra, which is the nearest thing, but it is generic text, not a function built from the agent's failure.
- M5 (text advice vs executable help): partly. Table 3 shows the same code output is adopted at 40.2% as a tool return and 1.8% as user text (-38.4 pp, Table 26). That is delivery channel, not note vs function, and the tasks differ across tools.
- M6 (mitigation): covered. Verify -4.0 / -4.0 / -9.8 pp with P0 kept; Compare stronger but costs P0; Low reliability label -4.0 pp; post-training mostly fails; steering model-dependent (Tables 5 to 7, 28 to 31, 36, 40; Figure 4). Mitigations are small relative to base adoption.

## What we can no longer claim

- That we are first to show agents adopt helper output without checking, or to measure that capable agents abandon answers they get right alone. The override rate is that measurement.
- That stronger models do not protect against tool overreliance as a new finding. This paper shows strength helps only partly and inconsistently, and accuracy does not predict resistance.
- That a verification prompt is a new mitigation. Verify, Compare, Disclose and reliability labels are tested here, with small effects.
- That tool-delivered output is trusted more than the same content as text as a new observation (Table 3, Code).
- Incidental: helper-driven success flattens across models. QuALITY P0 accuracy is 98.0 to 100 for models whose base accuracy is 28.3 to 49.4 (Table 19), and Code P0 is 99.3 to 100 (Table 33). We should cite this as consistent with "substitution", not claim the flattening itself is new.

## What stays open

- A helper built by a stronger model from the student's own failure, as a function vs as a note, on the same failures and the same students.
- Natural unreliability: a helper that is right most of the time, where harm comes from the student stopping early, not from injected wrong values.
- Net effect per student: gains on failed tasks vs losses on passed tasks, as a function of student strength.
- Whether helper success equals helper reliability for every student (substitution) while note success scales with ability (amplification). Never tested as a law here.
- Multi-step, stateful agentic tasks (AppWorld-style APIs). All tasks here are single-question.
- Lead to read next: Wang and Vemuri 2026, arXiv 2606.14476, "LLM agents defer blindly to graph neural network tools, and stronger backbones defer more" (cited in Section 2). It may cover M2 in the opposite direction from this paper.
