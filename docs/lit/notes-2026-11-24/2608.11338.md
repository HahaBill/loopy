# 2608.11338 · Better, Faster, Stronger: Programmatic Skill Learning Best Reduces Agent Cost (SpeedRunner)

- arXiv v1, 11 Aug 2026, cs.CL. Zixi Huang, Xiheng Wang, Andrew Wang, William Jurayj, Bernal Jiménez Gutiérrez, Daniel Khashabi, Nicholas Andrews (Johns Hopkins University). Found through the reference list of "Agent in a Bottle" (2610.08775).
- Read on 2026-11-24 from the arXiv HTML text dump: abstract to conclusion (lines 41 to 486) and every appendix (lines 942 to 1531). The reference list (lines 487 to 941) was skipped. All 12 figures and Table 1 were viewed in the PDF (pages 1, 3, 6 to 9, 18 to 21).
- **This is the closest paper we have found to the student-by-form question. Read the "Cross-model" part below first.**

## Claim

Skills written as programs cut an agent's cost more than skills written as prose, with no loss of task success. The agent learns the programs itself, online, with no replay. Key number: on BabyAI with GPT-5.4-mini, success rises from about 67% (no learning) to near 100% while output tokens fall to about one eighth (Section 5, Figure 3, Figure 8). The method is the only one whose cost goes down over training on all three benchmarks.

## Method

- Wake and sleep loop (Algorithm 1). Wake: the actor (an LLM with callable functions) runs 10 tasks. Sleep: an "inducer", a coding agent with a code interpreter, reads the stored trajectories with code, then adds, edits or deletes functions. Functions are public (shown to the actor) or private (helpers).
- No replay: a task is never run again with the new library. No held-out validation of a skill.
- One model plays both roles in every run. Main model GPT-5.4-mini (actor low reasoning effort, inducer medium). 200 rollouts, sleep every 10, test on a fixed 30 episodes every 50 rollouts, 3 seeds (Section 4.3, Appendix A).
- Baselines (Section 4.1): ReAct with no learning. OPO, the prose baseline: after each batch an LLM reads recent trajectories and rewrites the actor's prompt. ASI, code skills, append-only, with its replay check removed. Voyager, code skills, on Crafter only.
- Benchmarks: ScienceWorld (two task families), BabyAI (one subtask), Crafter. All text-based embodied games, chosen so that ReAct is neither trivial nor saturated.
- Cost: uncached input, cached input and output tokens of actor and inducer, inducer cost spread over its batch (Appendix A.3). Efficiency is reported as output tokens per episode.

## Results, including the weak ones

- GPT-5.4-mini (Figure 8): SpeedRunner is best or tied on success in all three and lowest in tokens. On ScienceWorld it only ties the prose baseline on success.
- Crafter is hard for every method (all under 30%).
- **Cross-model (Appendix G.2, Figures 9 to 11).** The comparison is repeated with Gemini-3-Flash and Qwen-3.5-27B. The authors write that the program method "achieves significantly worse final success rate than OPO with Qwen in ScienceWorld and Gemini in all benchmarks, despite achieving much lower token usage", and that "aggressive code delegation is not always performance-improving when the base actor is already strong". Both of these models start from a higher no-learning score than GPT-5.4-mini on the benchmarks where prose wins.
  - What Figure 9 shows (Gemini-3-Flash; x = training traces 0 to 200, y = success, shaded band = spread over 3 seeds). ScienceWorld: prose ends near 92%, programs near 80%, no learning near 68%. BabyAI: prose near 100%, programs near 85% at the end with a wide band, no learning near 93%. Crafter: no learning near 34%; programs drop to about 20% mid-training and end near 26%, so below no learning.
  - What Figure 10 shows (Qwen-3.5-27B). ScienceWorld: prose near 84%, programs near 69%, no learning 60%. BabyAI: programs near 95%, prose near 80%. Crafter: programs and the other code methods near 29%, prose near 23%.
  - The authors' explanation, not tested: the program library takes over most decisions (Gemini makes 94% fewer LLM calls on Crafter), which is cheap but "too rigid" when a situation needs judgment. "SpeedRunner can over-compress a capable actor."
- Removing the code interpreter mostly costs tokens, not success (Figure 7).
- Under more random Crafter worlds, prose memory falls below no learning; the program method stays above (Section 6.3). What Figure 5 shows: bars of final mean progression at zombie frequency 0x, 1x, 2x, with a dashed no-learning line near 0.15. Prose (OPO) about 0.20, 0.17, 0.05. Programs about 0.34, 0.25, 0.22. Voyager about 0.16, 0.13, 0.10. No error bars on the bars.

## Limits

- Theirs: no flagship models, no costly benchmarks, large seed-to-seed spread.
- Mine:
  1. The model that writes the skill is the model that uses it. There is no teacher and no weaker student.
  2. Prose and program arms differ in more than form: different learner, different update rule, different amount of analysis.
  3. Skills are learned from a stream of tasks, not built from one failure, and the two forms are never tried on the same failed task.
  4. "Stronger actor" means three different model families, one each. Strength is not varied with anything else held fixed.
  5. The reversal is reported at the level of a whole benchmark, in an appendix, with an explanation that is not tested. No per-task count of tasks a program broke.
  6. No control for "any prose helps".

## Overlap with Loopy (K1 to K6)

- K1 (note vs function, same failure, same teacher, same student): partly. Prose and program forms are compared on the same model and tasks, but self-learned, not teacher-built, and not on the same failure.
- K2 (does the best form depend on student strength): **partly, and this is the closest prior evidence.** Programs win on the weakest of three models and prose wins on the two stronger ones in 4 of 6 settings (Appendix G.2). Observed, not designed, with strength confounded with model family.
- K3 (task difficulty): not.
- K4 (executable help hurts a capable agent): partly. Gemini on Crafter ends below no learning with programs (Figure 9). No task-level harm count.
- K5 (controls): not. No generic-note control, no re-run gate (they remove it on purpose), no variants of one task.
- K6 (cost over uses): partly. Cost per episode including the inducer, no break-even, no failed-build accounting.

## What we can no longer claim

- That "a function can hurt a capable agent while helping a weak one" has never been seen. It is in this paper's Appendix G.2.
- That code skills are cheaper than prose skills per use.

## What stays open

- A designed test: the same failure, the same teacher, the same student, note against function, across students ordered by their own no-help score.
- Why it happens. Their word is "rigid". Our stage 1 rows point to something measurable: students call the function once and stop, and the function alone is right about nine times in ten whatever the student.
- Task-level harm counts, a generic-note control, variants of a repeating task, break-even with failed builds.
