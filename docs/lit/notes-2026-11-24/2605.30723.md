# 2605.30723v1: MASA (Model-Aware Skill Alignment)

arXiv 2605.30723, version v1, dated 29 May 2026 (cs.CL). License CC BY 4.0. Code: github.com/jianxiangyu/MASA_

Authors: Jianxiang Yu, Jiapeng Zhu, Bochen Lin, Qier Cui, Zichen Ding, Xiang Li (corresponding). All East China Normal University, Shanghai.

## Bottom line for Loopy

Closest prior work so far on K2 and on the "teacher writes advice from the student's failures, kept only if it helps" loop. It shows the same text skill helps one model and hurts another, with a crossover by text granularity across model sizes. It has **no executable form at all**. Every skill is natural-language text retrieved into context. So K1 (text vs code) and the form x capability question for code stay open. One direct lead for K1: SkVM (arXiv 2604.03088), cited in App. A, compiles skills into runtime formats including "code solidification".

## Claim

- Skill effectiveness is model-dependent; a skill that helps one backbone can hurt another (Sec. 2, Fig. 1, Table 5). Key case: Qwen3-8B is best with No Skill (32.1% ALFWorld) and all three skill granularities lower it (27.9, 25.0, 17.1).
- MASA, a teacher-driven search that rewrites skills per backbone, gets the best average SR on every backbone in ALFWorld, WebShop and search QA, with gains up to +25.8 points over the strongest baseline (Qwen3-8B ALFWorld, 57.9 vs 32.1; Table 1, Sec. 4.2).
- A 4B SFT rewriter trained on search traces beats a one-shot DeepSeek-V4-Pro rewrite on held-out ALFWorld task types (Fig. 3, Sec. 4.3): Cross-task +8.8 (8B), +13.2 (14B), +7.4 (32B).

## Method (reproducible detail)

- Agent (Sec. 3.1, Eq. 1): frozen backbone F. At each step it retrieves top-k skills by cosine similarity (encoder Qwen3-Embedding-0.6B) and acts. Only the skill library S is optimised.
- Library (Sec. 3.1), from SkillRL (Xia et al. 2026, arXiv 2602.08234): general skills S^G (cross-task principles) and task-specific skills S^Tc per task type c. Top-k_G and top-k_T retrieved separately. **k_G and k_T values are not given.**
- Model card (Sec. 3.1, App. D): architecture metadata, training provenance, capability profile. Strengths from release notes. Weaknesses written by the teacher from a small set of preliminary rollouts, disjoint from the eval set. No eval scores or style labels in the card. Qwen3-4B card shown in full.
- Reward (Eq. 2): R = SR - lambda * NHR. SR in {0,1}. NHR = "nothing-happens rate", the fraction of steps after which the environment state is unchanged. lambda in [0,1]. **The lambda value used is not given.**
- Teacher: DeepSeek-V4-Pro. Targets: Qwen3-4B/8B/14B/32B in non-thinking mode (Sec. 4.1, footnote 2).
- Stage 1, general skills, hill climbing (Sec. 3.2, Alg. 1, App. E.1): roll out F with current best S^G on all task types; teacher analyses failures into a structured failure attribution; teacher rewrites given current best, attribution, model card and the top-K=5 historical skill sets; evaluate the candidate on the full suite; **accept only if its reward strictly beats the current best**. I=10 max iterations, patience p=3. Eval set D is sampled from training episodes; its size is not given.
- Stage 2, task-specific skills, per-type UCB tree search (Alg. 2, App. E.2): UCB1(n) = Rbar(n) + C sqrt(ln N_parent / N_n), C=1.4. Each expansion: roll out, collect failures, teacher attribution, teacher rewrite as a child node, evaluate on that type, back up. J=10 iterations per type, N=100 episodes per node evaluation. Final = highest-value node. S^G fixed from Stage 1.
- Evolution uses the training split; reported results use a held-out split (App. E). Note: Sec. 2.1 says "validation split", App. E says "held-out test split". Not reconciled.
- Rewriter (Sec. 3.3, App. F): Qwen3-4B, full-parameter SFT, BF16, AdamW lr 1e-5, cosine, warmup 0.1, effective batch 4, 5 epochs, max length 4096, checkpoint chosen by **training loss** (no validation). Input (model card, input skill set, task description) to output an evolved high-scoring skill set (Eq. 4 to 6). Inputs sampled from search intermediates, cross-model transfers, one-shot teacher rewrites, and noisy (0.3), partial (keep 0.6) or verbose perturbations. Two variants: 769 samples (Search + WebShop + ALFWorld Pick/Look/Pick2) and 499 samples (WebShop + Search). The App. F sentence describing the 769-sample set is garbled.
- Baselines (Sec. 4.1): No Skill; Base Skill (SkillRL library shared by all backbones, also MASA's starting point); DS-Adapter (one-shot teacher rewrite conditioned on the model card, no search). Rewriter study adds 4B-Rewrite (untrained Qwen3-4B as rewriter).
- Preliminary study (Sec. 2.1, App. C.1, Table 4): same principles, three text granularities. Moderate = SkillRL library. Concise and Detailed made by "controlled rewriting". Token sizes only in the Fig. 1 legend: Concise ~370, Moderate ~1,092, Detailed ~2,737 tokens.

## Setting, data, models

- ALFWorld: 6 task types (Pick, Look, Clean, Heat, Cool, Pick2). From the percentages in Table 1 the per-type counts look like 35/13/27/16/25/24 = 140 episodes (my inference from denominators; e.g. 53.8 = 7/13). One Look episode = 7.7 points.
- WebShop: SR, score, steps; 7 product categories (Table 8).
- Search-augmented QA: NQ and HotpotQA in-domain (used for evolution); TriviaQA, PopQA, 2Wiki, MuSiQue, Bamboogle out-of-domain.
- Backbones: Qwen3 4B/8B/14B/32B; Gemma3 4B/12B/27B only in the preliminary sweep (App. C.3).
- Step budget per episode, seeds, number of runs: not given. Results look like single runs. No error bars or tests anywhere.

## Metrics

- SR: percent of episodes solved. ALFWorld "SR" is over all types; "Steps" = average interaction steps.
- WebShop: SR, WebShop score (the standard attribute-match score), steps.
- QA: success rate per dataset; "Avg." is **not** the simple mean of the seven columns (Qwen3-4B No Skill columns average 26.3, reported 32.9). Probably sample-weighted; not stated.
- Search objective R = SR - lambda NHR (above).

- Crossover: Detailed text hurts the small models (Qwen3-4B, Qwen3-8B, Gemma3-4B) and helps the large ones (Qwen3-14B/32B, Gemma3-27B). The authors stress non-monotonicity (Finding 2: Qwen3-32B is 4.6 below 14B under Detailed; 4B peaks at Moderate).
- Smallest model gains least from MASA (4B: +4.3 over best baseline ALFWorld). Authors attribute it to a "capability ceiling" (Sec. 4.2, obs. 3). On n=140 episodes, +4.3 is about 6 episodes, single run.
- Larger Qwen3 models do worse than 4B on WebShop without adaptation (14B 2.8% vs 4B 23.0%). Table 7: CoT preamble in 0% (4B), 57% (8B), 97% (14B), 66% (32B) of steps; action length 73, 1,021, 574, 491 chars. MASA fixes this (SR 26.4/28.6/29.2/34.6, steps 7 to 8).
- MASA also cuts ALFWorld steps (8B 39.1 to 29.2; 14B 36.7 to 25.7).
- Negative or weak points the text glosses:
  - MASA is not best on every task type: 4B Pick 25.7 vs DS-Adapter 28.6; 4B Cool 24.0 vs 32.0; 8B Look 38.5 vs No Skill 46.2 (Table 1). The claim "MASA avoids these regressions" is not fully true.
  - WebShop per category (Table 8): 4B Electronics 71.4 (No Skill) to 28.6 (MASA); 8B Accessories 20.0 to 10.0.
  - QA (Table 2): MASA below No Skill on 8B 2Wiki (30.6 to 25.7), 8B Bamboogle (68.1 to 62.5), 14B Bamboogle (10.5 to 8.9), 4B HotpotQA in-domain (27.7 to 27.4). QA gains are small (+1.4 to +5.9 avg).
  - Bamboogle values are bimodal (about 8 to 15 in some cells, about 61 to 68 in others, e.g. 8B No Skill 68.1 vs Base Skill 10.1). The "12.9 to 61.3" headline on 4B comes from this column. Looks unstable or buggy; not explained.
  - One-shot tailored rewriting (DS-Adapter) is unreliable: worse than No Skill on 8B ALFWorld and on all four WebShop backbones; worse than Base Skill on 3 of 4 WebShop backbones and on 8B in Fig. 3.
  - Untrained 4B-Rewrite is below Base Skill on all 4 backbones (Fig. 3).
  - Rewriter without model card collapses: 4B Cross-task 8.8 vs Base Skill 22.0 (Table 3b, Fig. 3).
- Ablation (Table 3a), removed stage replaced by one-shot teacher rewrite: ALFWorld w/o task-specific search -6.4/-25.0/-0.7/-15.7; w/o general search -6.4/-7.9/-16.4/-1.4. WebShop w/o general falls to 7.2/10.2/9.6 for 8B/14B/32B.

## Limitations

Theirs: Qwen3 only for the main results; closed models need hundreds of paid rollouts; needs environments with automatic success signals; evolved skills may carry unsafe heuristics.

Mine:
- Single runs, no seeds, no error bars, no significance tests. Per-type cells move 4 to 8 points per episode.
- Key hyperparameters missing: lambda, k_G, k_T, Stage 1 eval set size, step budget, teacher sampling.
- Search cost not reported. My lower-bound estimate for ALFWorld Stage 2 alone: 6 types x 10 iterations x 100 episodes = 6,000 episodes per backbone, plus Stage 1 and failure collection. Rejected candidates are not counted anywhere.
- The "rewriter beats the teacher at a fraction of the cost" claim has no cost numbers.
- Rewriter checkpoint chosen on training loss.
- Fig. 5 text contradictions and the Table 2 Avg and Bamboogle oddities.
- "Model strength" is confounded with family behaviour: Qwen3-8B to 32B are worse than 4B on WebShop at baseline because of verbose CoT, so size is not a clean capability axis.
- Base Skill is a real library, not a placebo. There is no length-matched irrelevant-text control, so "any extra context hurts" is not separated from "this content hurts".

## Untested assumptions

- That the failure mode is in skill expression, not in the retrieval step (retrieval is fixed and never ablated).
- That a model card text actually carries capability information the teacher uses (ablated only for the rewriter, not for the search).
- That gains on the training split generalise; held-out split is from the same task types, so it is variant transfer, not new tasks (except the rewriter OOD study).
- That NHR is a good proxy for skill-induced stalling.

## Overlap with Loopy

- K1 (same failure, same teacher, same student: text vs executable): **not covered**. All skills are text, including the 32B "algorithmic" rule (Table 9). Lead: SkVM (arXiv 2604.03088) compiles skills with "code solidification" and reports 87% of tasks have at least one LLM that gains nothing from the same skill (App. A). Must read for K1.
- K2 (capability axis, form x strength interaction): **partly**. Strong evidence of a form x model interaction with a crossover (Detailed text: -15.0 on Qwen3-8B, -10.7 on Gemma3-4B, +9.6 on Qwen3-14B, +22.9 on Gemma3-27B). But the forms are text granularities and generic vs tailored text, never text vs code.
- K3 (task difficulty, text fading, code holding): **not covered**. Per-type and single- vs multi-hop splits exist (Finding 3: 60+ point spread across types), but no difficulty ordering and no executable form.
- K4 (non-text help harming capable students): **partly, text only**. Text skills harm some models (Qwen3-8B, Gemma3-4B) and MASA itself harms some cells (8B Look, 4B Electronics). The most-harmed models are small or mid-size, not the strongest. Nothing executable is tested.
- K5 (controls): **partly**. Generic control = Base Skill (shared library, not a placebo). One-shot tailored unchecked control = DS-Adapter. Keep-if-better = accept only if reward on the training eval set strictly beats the current best (Alg. 1). This is a library-level check on a sample, not "the student re-runs and passes the task the note came from". Variants of a repeating task = ALFWorld train-to-held-out episodes of the same six types. No placebo note.
- K6 (cost and break-even with failed builds): **not covered**. Only steps per episode and "hundreds to thousands of rollouts".

Plain answers:
- Does the gain from a skill change with model strength? Yes. For searched, tailored text, the smallest model gains least (ALFWorld +14.3 for 4B vs +25.8, +26.4, +29.3 for 8B, 14B, 32B; WebShop +3.4 vs +24.0, +26.4, +28.0). For generic detailed text, small models lose and large models gain (table above). Direction: text skills help stronger models more and can hurt weaker ones. Not monotone in size (Qwen3-8B is hurt most).
- Do skills include scripts or executable parts? No. Text only. No separation needed because there is no executable part.
- Any case where a skill hurts a strong or weak model? Yes, weak to mid: Qwen3-8B ALFWorld 32.1 to 25.0 (Base) and 17.1 (Detailed); Gemma3-4B 10.7 to 0.0 (Detailed); Qwen3-4B WebShop 23.0 to 19.4 (Base). Among the larger models, harm is cell-level only (e.g. 32B 2Wiki 29.3 to 26.0 with Base Skill).
- Any analysis by task difficulty? Only per task type and single- vs multi-hop. No difficulty axis.

## What we can no longer claim

- That model-dependence of advice or skill benefit is new, or that a generic skill can hurt one model while helping another. MASA shows both, across two families.
- That a stronger teacher writing student-specific advice from the student's own failure trajectories, kept only if it improves the score, is new as a method. MASA's Stage 1 and 2 do this.
- That "one-shot tailored text is unreliable, checked or searched tailored text works" is our finding. DS-Adapter vs MASA already shows it.

## What stays open

- Text vs executable help from the same failure (K1). Nobody here tests code.
- Whether the best FORM (text vs code) flips with student capability (K2 for form). MASA's pattern (text helps strong models more, weakest gains least) predicts that weak students need a non-text form. That is a testable prediction for Loopy, not shown by MASA.
- Difficulty x form (K3), executable harm to capable students (K4), placebo control and per-failure re-run check (K5), break-even with failed builds counted (K6).
- Leads to read in full: SkVM (2604.03088) for K1; SkillRL (2602.08234), the base library MASA starts from.
