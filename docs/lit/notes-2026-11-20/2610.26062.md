# Procedural Exposure Bias in Skill-Augmented Language Model Agents

- arXiv: 2610.26062v2 [cs.CV], 27 Oct 2026. Yang, Xiong, Huang, Xu, Liu, Chen, Gu, Yu (Northeastern University Shenyang; Alibaba). Code: github.com/NEUIR/Vis-Skill
- Read on 2026-11-20 from the arXiv HTML text dump (3775 lines) and the 26-page PDF.
- Section, table and figure pointers below refer to the paper.

## Claim

When a skill text repeats a word tied to an action, the model leans toward that action. This happens even when the action does not apply in the current state. The authors call it Procedural Exposure Bias (PEB). Showing the same skill as an image instead of text weakens the effect.

Key numbers:
- Qwen3.5-9B, 165 ALFWorld decision steps. Preference for a wrong (state-inapplicable) action rises from about 0.046 with 0 mentions to about 0.133 with 8 mentions under text. Under image input it rises from about 0.040 to about 0.080 (Figure 1a, values read off the plot; bar labels 0.13 and 0.08 in Figure 1c).
- Slope of the wrong action's summed log-probability per extra mention: 0.741 (text), 0.467 (plain image of the text), 0.552 (styled skill card) for Qwen3.5-9B. For Gemma-4-31B-it: 2.657, 1.283, 1.361 (Appendix A.5.1, Figure 3a, Figure 8).
- In free generation, the rate of picking an allowed but wrong "competing" action at 8 mentions is 11.4% (text) vs 4.9% (image) for Qwen3.5-9B, and 8.6% vs 4.4% for Gemma-4-31B (Figure 3c). Slope 0.0091 per mention under text (R2 = 0.95) vs 0.0026 under image (R2 = 0.48). Slope difference 0.0065, bootstrap 95% CI [0.0011, 0.0120] (A.5.3).
- End to end, image skills beat text skills on macro success for all four models, by 0.9 to 3.4 points (Table 1).

## Method (enough to reproduce)

Controlled probe (Section 2.1, Appendix A.1):
1. Take 165 intermediate steps from successful ALFWorld trajectories. Replay each in the simulator to rebuild the observation history and the admissible action set. Strip any skill text from the history.
2. For each step, the correct action is the one in the reference trajectory. Add a distractor action. It must be relevant to the overall task, name a real object in the scene, use a different verb from the correct action, and NOT be in the admissible set at this step.
3. Each distractor has a target keyword, an object noun (example: "microwave" for "open microwave"). The keyword must appear in the 37-skill corpus and must not appear in the task query or the correct action.
4. Supply five ranked skills. First replace all native occurrences of the keyword in those skills with neutral one-word substitutes (skill names stay). Then fill fixed insertion slots spread over the skill text. At exposure level k in {0, 1, 2, 4, 8}, exactly k slots hold a phrase with the keyword. The other slots hold filler phrases of the same word count. Total word count is constant across k. Token count is not guaranteed constant.
5. Score a fixed candidate set: up to 16 admissible actions (look, inventory, help, wait, examine removed) plus the distractor. Score = length-normalized token log-probability under teacher forcing with a fixed prefix (Eq. 2). Normalize with a softmax over the candidate set (Eq. 6). "Distractor preference" is that normalized value. It is not a generation probability.
6. Visual condition: render the same skill as a structured skill card image and feed it through the model's own vision encoder. Rasterized condition: plain monospaced image of the same text.
7. Controls at k = 8: replace the target keyword with a neutral word (target-replacement); replace an unrelated word of the same frequency (frequency-matched control, available for 128 of 165 states).

Other probes:
- Readout (A.5.2): ask the model for the most frequent object in the skill, at k in {0, 4, 8}. Score the probability of the target word at the answer position.
- Executable action selection (A.5.3): a separate set of 185 states from 64 successful trajectories. The competing action is admissible and task-relevant but differs from the reference action. Greedy decoding. Count how often the model outputs the competing action.
- Paired rollouts (A.5.4): from each of the 185 states, branch the environment. One branch executes the correct action first, the other the competing action. Then the model continues greedily. Budget = min(40, remaining expert steps + 20). Qwen3.5-9B only, k in {0, 4, 8}.
- Layer-wise readout (A.5.5): apply final norm and LM head to each layer's hidden state at the action positions (logit lens). Report mean change in distractor log-probability vs k = 0.
- Activation patching (A.5.6): cache component outputs from the k = 8 run, paste them into the k = 0 run at the action positions, measure how much of the score change is recovered.

End-to-end evaluation (Section 5.1): No Skill, Text Skill, Visual Skill. Following SkillNet, Qwen3.8-Max ranks a shared skill library per task from task type, name and goal (prompt in Table 2). Text and Visual get the same ranked skills.

## Setting, benchmarks, models

- Benchmarks: ALFWorld, ScienceWorld, WebShop. All text-game style, step-by-step action choice. No code-writing agent, no API tasks.
- Models: Qwen3.5-9B, Qwen3.5-27B, Gemma-4-31B-it, Kimi-K2.5. Controlled probes use only the first three (Kimi appears only in Table 1).
- Evaluation set sizes are not stated. From the percentages they look like 134 ALFWorld tasks, 211 ScienceWorld tasks and 200 WebShop tasks (my inference).
- No seeds, repeats or confidence intervals are reported for Table 1.

## Metric, exact definitions

- Procedural exposure frequency: whole-word count of the target keyword in the supplied skill (Eq. 1).
- Distractor preference: softmax-normalized, length-normalized log-probability of the distractor over the fixed candidate set (Eq. 2, 6).
- Paired change (Figure 1b): same, but with summed (not length-normalized) log-probabilities, k = 8 minus k = 0 (Eq. 7).
- Exposure sensitivity: per-state slope of the distractor's summed log-probability on k (Eq. 9).
- Competing-action selection rate: share of 185 states where greedy output equals the competing action (Eq. 12).
- Task success rate: share of tasks completed. Macro success = plain mean of the three benchmark success rates. WebShop success = share of episodes with reward 1.

## Results, including weak and negative ones

Table 1 (macro success, No Skill / Text / Visual):
- Qwen3.5-9B: 16.21 / 40.70 / 44.06
- Qwen3.5-27B: 41.33 / 53.06 / 53.94
- Gemma-4-31B: 41.02 / 57.24 / 58.21
- Kimi-K2.5: 49.73 / 56.34 / 58.64

Text skill gain over no skill: +24.5 (9B), +11.7 (27B), +16.2 (Gemma), +6.6 (Kimi). The weakest model gains most. Visual minus Text: +3.4, +0.9, +1.0, +2.3.

Weak or negative points:
- The Text vs Visual gap is a handful of tasks. With my inferred set sizes, Qwen3.5-27B gains 3 tasks on ALFWorld and 4 on ScienceWorld and loses 3 on WebShop (23.00 vs 21.50). Gemma ties on ALFWorld (90.30 both). No significance test.
- Skills sometimes hurt. WebShop, Qwen3.5-9B: text skill 13.50 vs no skill 14.00 (Table 1).
- Per-category harms the authors do not discuss (Tables 3 and 5). ALFWorld Examine, Qwen3.5-27B: 83.33 no skill, 61.11 text, 44.44 visual. ALFWorld Pick2, 27B: 82.35 no skill, 70.59 text. ScienceWorld Elec., 9B: 36.67 no skill, 20.00 text. ScienceWorld Life, 9B: 70.00 no skill, 56.67 text, 60.00 visual. ScienceWorld Meas., 27B: 75 to 60 under both. Kimi ScienceWorld Stages: 11.11 no skill, 0.00 text.
- Visual is not better everywhere. Examples: ALFWorld Heat, all three open models are lower under Visual than Text (57.14 to 50.00, 65.22 to 56.52, 78.26 to 69.57).
- Larger models are not less biased. Under text, sensitivity is 0.741 (9B), about 1.1 (27B, read off Figure 8a), 2.657 (Gemma-31B). Gemma's distractor preference under text jumps from about 0.01 to about 0.21 at k = 8 (Figure 7a).
- The "signal is still readable under image input" claim is weak for the small model. Probability of answering with the keyword at k = 8: Qwen3.5-9B 22.6% text vs 6.2% visual. Gemma 59.6% vs 42.1% (Figure 3b). So the image does lose signal. The authors say the probe "does not establish equal accessibility".
- Paired rollouts (Tables 7, 8): even after the correct action is executed for it, Qwen3.5-9B with skills finishes only 30.27%, 40.54%, 34.05% of episodes (text, k = 0, 4, 8) and 25.41%, 41.08%, 39.46% (visual). Taking the competing action first lowers success to 26 to 32% and adds +2.31 steps [1.61, 3.21] (text, pooled) or +2.43 [1.26, 3.90] (visual) among pairs where both succeed. McNemar p = 0.694, 0.025, 0.081 (text) and 0.185, 0.030, 0.081 (visual). So the success cost is significant only at k = 4. Success is not monotone in k and the authors do not explain why. Mean steps are about 8 under text and about 16 under visual, also unexplained.
- Patching gives no single mechanism. MLP patching moves the score in the opposite direction in both Qwen models and in the same direction in Gemma (Figure 5, Figure 10).
- The authors state that Table 1 does "not establish whether reduced procedural exposure bias fully explains the performance advantage" (Section 5.1).

## Limitations

Authors' own (scattered hedges, there is no limitations section):
- Table 1 does not show that less PEB is why visual wins.
- The readout probe does not show equal accessibility across representations.
- The frequency-matched control uses 128 of 165 states, so it is not fully paired.
- Word count is fixed across k, token count is not.
- Paired rollouts do not estimate the effect of exposure on full-agent success.
- Logit-lens readouts and patching do not identify the computation.

Mine:
- The exposure is synthetic. Keyword phrases are stuffed into slots. Natural skills are not shown to have this much repetition, and no experiment removes natural repetition from a text skill and measures task success. So the link from PEB to real failures is not made.
- The main probe scores an action that the environment would reject. The executable-action version shows a much smaller effect (4% to 11%).
- Image input may simply make the model use the whole skill less, good parts and bad parts. The 9B readout (6.2% vs 22.6%) points that way. A "use less of the skill" account would also explain a lower bias.
- End-to-end differences are small, from one run, with no error bars and unstated set sizes.
- All controlled work is on ALFWorld. Kimi-K2.5 is never probed.
- The source of the "successful trajectories" (which agent produced them) is not stated. The aggregate slope fit in A.5.3 does not say which model it is for.
- No analysis of failed episodes. The paper never asks whether the agent followed the skill.

## Assumptions not tested

- That a count of one object noun is a fair stand-in for "exposure of a procedural pattern". The introduction says n-gram frequency; the experiments use single nouns.
- That the attention-aggregation story in Section 3.1 (more positions carrying the keyword means more pull) is the cause. It is stated, not tested. The patching results do not support one simple path.
- That lower PEB causes the higher success under visual input.
- That filler phrases are neutral.

## Mapping onto Loopy components

- C1 (forms of transferred knowledge, same failure, same teacher, same student): not covered for advice vs program. Partly covered in a narrower sense: the same skill content in three surface forms (text tokens, plain image, styled card) for the same student (Table 1, Figure 3a, A.5.1). There is no teacher and no executable form.
- C2 (student strength): partly. Four students. Skill gain shrinks as the no-skill baseline rises (+24.5, +11.7, +16.2, +6.6 macro, Table 1). No analysis of when advice is enough. Bias does not shrink with size from 9B to 31B (Figures 1, 6, 7, 8).
- C3 (predict the remedy before paying): not covered.
- C6 (harm from skill use): partly. One mechanism: repeating an action's keyword in a skill pulls the agent to that action when it does not apply (Section 2, Figures 1, 3c). Raw harm cases are visible in Tables 1, 3, 5 but not analyzed. Cost of one wrong step: about +2.3 steps and lower completion (Tables 7, 8).
- C7 (execution gap): partly. The paper's framing is "accessibility does not necessarily guarantee effective utilization" (Section 1) and it separates "signal accessibility" from "use as action evidence" (Section 5.2, Figure 3b). It measures one cause of wrong action choice with the skill in context: log-prob shift and selection rate as a function of repetition. It explains it by attention over repeated tokens (untested) and shows where it appears in depth (Figures 4, 9). It does not define or measure the general gap (success given a correct procedure), and does not split failures into "did not follow the skill" vs "followed it and failed". Size dependence: tested on 9B, 27B, 31B only; no downward trend.

## What this means for Loopy

What we can no longer claim:
- That we are the first to say that having the right procedure in context does not mean the agent uses it. This paper says it in its introduction and cites four works for it that we should read: SkillsBench (2602.12670), "How well do agentic skills work in the wild" (2604.04323), "Skill-use: can LLMs actually use skills in agentic harnesses?" (2608.04828), "Demystifying agent skills: why they work until they don't" (2608.14036).
- That a text note is a neutral carrier. How often the note names an action changes what the small model does, apart from whether the action fits the current step.

What is still open after this paper:
- It never compares text advice with a program. It never looks at a code-writing agent. It never shows a model that knows the steps and fails to carry them out; its failure is being pulled to a wrong step.
- It has no model below 9B and no explanation tied to model size.

Design lessons to copy:
- Keep COACH notes free of repeated API or action names. Name each call once. Do not mention calls that belong to the task but not to the failing step. When comparing note variants, hold word count fixed.
- Separate "read the note" from "acted on the note". Their readout probe asks the model a direct question about the skill content and compares that with its action choice. For us: after a coach failure, ask the small model what the note says to do at the failing step. If it answers right and still acts wrong, that is the execution gap. If it answers wrong, it is a reading problem.
- Fixed-candidate scoring at the failing step. If the small model exposes log-probs, score the correct next call against the call it actually made, with and without the note. This shows whether the note moves action evidence at all, with far fewer runs than full episodes.
- Paired rollouts from the failing state (branch with the correct step forced vs the model's own step) to price one wrong step. Their Qwen3.5-9B finished only 25 to 41% of episodes even with the correct step forced, which says later steps fail too.

Experiment that would extend it:
- PEB in a code-writing agent on AppWorld. Vary how many times a COACH note names one API (0, 1, 2, 4, 8) at fixed word count and count how often the small model calls that API at the wrong time.
- Treat COMPILE as the limiting case of changing the representation. A function removes the action choice that PEB biases. Compare coach text, coach text with repetition removed, and compile on the same failures.
- Run the readout-vs-action split on our three "procedural" coach failures and on models smaller than 9B.
