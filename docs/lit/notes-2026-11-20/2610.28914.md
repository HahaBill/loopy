# D-Skill: Distilling Teacher Knowledge through Agent Skills

- arXiv: 2610.28914v2, 3 Nov 2026. Yuan, Li, Gonzalez (UC Berkeley). Code: github.com/shuo-yuan/D-Skill
- Read on 2026-11-20 from the arXiv HTML text dump (1637 lines) and the 21-page PDF.
- Section, table and figure pointers below refer to the paper.

## Claim

A strong "teacher" agent and a weak "student" agent each run the same unlabeled tasks once. A strong analyst model compares the two traces and writes lessons. The lessons are merged into one text skill file (SKILL.md) that the student reads at inference time. No weights change. No labels are used.

Key number: the skill closes 75% to 95% of the teacher-student gap (Table 1, Section 4.1).
- SpreadsheetBench-Verified (SSB-V): 83.4% to 89.3% of the gap. Example: Qwen3.6-35B-A3B goes from 28.0 to 71.7 with a teacher at 79.3 (Table 1a).
- ALFWorld: 84.6% to 94.6%. Example: GPT-5.6 Luna goes from 55.2 to 83.1 with a teacher at 84.7.
- Chess puzzles: 75.3% and 87.7% (Table 1b).

Second number: the student with the skill costs 8.3x less per task than the teacher on SSB-V and 5.7x less on ALFWorld (Figure 4, Section 5.3). One-time build cost is $3.28 for 99 SSB-V tasks and $1.51 for 57 ALFWorld games (Table 6).

## Method (enough to reproduce)

Three stages (Section 3, Figure 2).

1. Rollout collection (3.2). For each task, one student trace and one teacher trace. Each model works alone. Traces record actions and observations. Saved logs can be reused. After this step neither model is called again and the environment is not touched.

2. Difference analysis (3.3, Appendix B). One analyst call per trace pair.
   - Input: task instruction, the "expert" trace, the "student" trace. For SSB-V also the graded answer range and the cells each agent left there (max 4,000 characters). No gold values.
   - Each trace is cut to its first 10,000 and last 35,000 characters.
   - Teacher reasoning, teacher system prompt and teacher skill text are stripped before the analyst sees the trace (Section 4, Models).
   - The analyst is told it has no answer key and must not judge who solved the task. It only describes how the expert's way of working differs.
   - It compares along fixed behavior dimensions: what was inspected before acting, how actions were chosen, how errors were handled, how the result was verified.
   - Output: at most 3 items per pair, ranked by expected impact. "Failure Memory Item" = what the student did, what the expert did, ONE reusable instruction. At most 1 "Success Memory Item" = a shared behavior to keep. Every item must quote trace evidence, must generalize beyond the instance, and must include one concrete check the student can run at runtime.
   - The full prompt template is in Appendix B.

3. Skill update (3.4). A modified Trace2Skill consolidator. The lesson pool is shuffled and split into k chunks (k is not given). For each chunk: map (each lesson becomes a candidate patch: append, replace or new section), reduce (merge, drop duplicates, resolve conflicts, generalize), apply (deterministic edit of SKILL.md). Chunks are processed in sequence.

Is the skill validated by re-running the student? No. The native pipeline has no validation gate at all. Only the SkillOpt-backed variant (Table 4) keeps SkillOpt's held-out gate, and it scored a bit lower (36.9 vs 39.0, inside the noise).

How many teacher calls? The teacher runs each distillation task once (99, 57 or 100 episodes). The analyst makes one call per pair. The consolidator makes a few calls per chunk. The teacher model is never asked to write anything; the analyst and consolidator are separate strong models.

Output is one global skill per benchmark and per teacher-student pair. It is not a per-task note.

## Setting, benchmarks, models

- SSB-V: 400 spreadsheet tasks. 200 held out for evaluation. 99 of the other 200 used for distillation.
- ALFWorld: 57 training games for distillation, the standard 134-game test split for evaluation.
- Chess: Lichess puzzles with six static analysis tools, max 10 tool calls per move (Appendix A, Table 7). 100 puzzles for distillation, 200 for evaluation (50 per 400-point rating band, 400 to 2000).
- Teachers for SSB-V and ALFWorld: DeepSeek-V4-Pro-0423 and GPT-5.6 Terra. Each teacher is given an existing skill "solely to strengthen the teacher".
- Students: Qwen3.6-35B-A3B (open weights) and GPT-5.6 Luna.
- Analyst and consolidator for SSB-V and ALFWorld: DeepSeek-V4-Pro-0423.
- Chess pairs: Sonnet 5 teaches Haiku 4.5 (Claude Code harness). Haiku 4.5 teaches Qwen3.6-35B-A3B (text-tag harness). Sonnet 5 is analyst and consolidator.
- Model sizes are not stated beyond the names.

## Metric

- SSB-V accuracy, ALFWorld success rate, chess strict solve rate (all solver moves correct). All on a 0 to 100 scale.
- GapClosed(s) = (J(student with skill) - J(student)) / (J(teacher) - J(student)) (Section 3.1).
- Chess also gives an estimated Elo from a logistic fit of solve probability against puzzle rating (Appendix A).
- Student and teacher: mean and standard deviation over 2 evaluation passes. D-Skill: over 6 evaluations (3 independently distilled skills x 2 passes).

## Results, including weak and negative ones

- Main (Table 1a). DeepSeek teacher: Qwen 28.0 to 71.7 (85.1%), Luna 25.3 to 73.3 (89.0%) on SSB-V, teacher 79.3. ALFWorld: Qwen 59.0 to 84.2 (85.7%), Luna 55.2 to 83.3 (84.6%), teacher 88.4. Terra teacher: Qwen 73.1 (89.3%), Luna 69.7 (83.4%) on SSB-V, teacher 78.5. ALFWorld both 83.1 (93.8% and 94.6%), teacher 84.7.
- Chess (Table 1b). Haiku 4.5 41.2 to 52.5, teacher Sonnet 5 at 56.2 (75.3%). Qwen 24.8 to 39.0, teacher Haiku 4.5 at 41.0 (87.7%).
- Which traces matter (Table 2, SSB-V, DeepSeek teacher). Student trace only: 47.7 (Qwen) and 49.8 (Luna), 38% to 45% of the gap. Teacher trace only: 56.3 and 63.5, 55% to 71%. Paired: 71.7 and 73.3. The one-sided variants also have much larger spread (standard deviation 5 to 9 vs 1 to 4).
- Who analyzes (Table 3, chess, Qwen student). Strong analyst + strong merger 39.0 (88%). Strong analyst + weak merger 34.3 (59%). Weak analyst + strong merger 31.1 (39%). Weak analyst + weak merger 32.6 (48%). So the analyst must be strong. The weak merger writes a much longer document.
- Other backend (Table 4, chess). SkillOpt alone 29.6 (29.7%). D-Skill lessons fed into SkillOpt 36.9 +/- 5.7 (74.9%). Native D-Skill 39.0 (87.7%).
- Against Trace2Skill (Table 5, SSB-V). Published setup: 33.0 and 31.1 (about 10% of the gap). Teacher-authored from teacher traces: 34.2 and 37.0. Teacher-authored from student traces: 36.0 and 46.2. Negative point: giving Trace2Skill the teacher's traces made it worse than giving it student traces.
- Against fine-tuning (Figure 3, Tables 8 and 9, Qwen student, LoRA rank 16). SSB-V after one pass: D-Skill 75.5 (one lineage), SFT on actions 49.5, SFT on reasoning + actions 55.5. After epochs 2 to 5, SFT reaches 54.3 to 64.5 and 61.5 to 72.3. ALFWorld after one pass: D-Skill 82.5, SFT 75.8 and 78.8. Weak point for D-Skill: on ALFWorld, multi-epoch SFT with reasoning reaches 83.5 to 86.6, which is above D-Skill.
- Negative for SFT: action-only SFT on SSB-V drops to 17.0 after 40 episodes, below the 28.0 floor (Table 8).
- Cost (Figure 4, Table 6). Covered under figures and under C4 below.
- The skill makes the student more expensive than the bare student: 0.35 vs 0.11 cents on SSB-V (3.2x) and 2.0 vs 0.82 cents on ALFWorld (2.4x). The authors say this comes from reading the document and from extra interaction steps it induces (Section 5.3).

## Limitations

Authors' (Section 6):
1. Needs a strong analyst at build time.
2. The skill raises inference cost over the bare student.
3. It can only transfer what can be said as instructions and carried out by the student. It cannot add missing capability (deeper calculation, perception, capacity). This is asserted, not measured.

Mine:
- The teacher is a model plus a pre-existing skill on SSB-V and ALFWorld. The student's gain may be partly a reconstruction of that hidden skill from behavior. Only the chess pairs use what look like bare teachers, and there the gap closed is a bit lower (75% to 88%) and the gap itself is small (15 to 16 points).
- Two evaluation passes for baselines. Standard deviations up to 8.8.
- No per-task analysis. We do not know which tasks flipped from pass to fail.
- The skill is one global document per benchmark, tested on held-out tasks of the same benchmark. Nothing is said about a task that repeats.
- Table 6 does not say whether rollout collection (99 teacher runs plus 99 student runs) is inside the $3.28. The text describes only analyst and consolidator calls. It also does not say which model was the analyst for that costing, since the main runs used DeepSeek as analyst.
- No tokens, no wall time, no count of cloud calls.
- The number of chunks k and chunk size are not given.
- Figure 3 uses one D-Skill lineage (75.5), which is above the 6-run mean (71.7).
- The two Haiku 4.5 rows in Table 1b come from different harnesses (footnote).

## Assumptions not tested

- That text is the right form. No executable artifact is compared. AgentDistill (MCP modules) is cited but not run.
- That the result holds for students weaker than Qwen3.6-35B-A3B or Luna.
- That a note built from few traces works. The smallest corpus is 57 pairs. Figure 3 gives a partial view (about 20 SSB-V pairs get roughly 40% of the way).
- That a missing validation step does no harm. No acceptance test by re-running the student.
- That stripping correctness information from the analyst is harmless. Not ablated.
- That the gain survives when the teacher has no hidden skill (SSB-V and ALFWorld).

## C1 to C6 mapping

- C1 (forms of knowledge, text vs program): not covered. Only text skills. The one "form" comparison is text vs weight updates (Section 5.2, Figure 3). Limitation 3 names the boundary but does not test it.
- C2 (student strength): partly. Two students on SSB-V and ALFWorld, two more pairs on chess (Table 1). Both students land in the same place. No sweep, no threshold, no case where text was not enough.
- C3 (predict before paying): not covered. The analyst is forbidden to judge correctness. No forecast of whether the skill will help.
- C4 (economics): partly. Per-task inference cost in cents (Figure 4). One-time build cost in dollars (Table 6). No break-even, no failed builds, no rollout cost, no tokens or wall time. My own arithmetic from their numbers: on SSB-V the saving is 2.55 cents per task, so $3.28 is recovered after about 129 tasks. If the 99 teacher and student rollouts are added (about $2.98), about 246 tasks. On ALFWorld the saving is 9.7 cents, so about 16 episodes, or about 89 with rollouts.
- C5 (online per-task choice): not covered. Fully offline, one global skill, always on.
- C6 (harm): mostly not. No per-task harm count. Indirect signs only: the skill-equipped student costs 2.4x to 3.2x the bare student, the D-Skill curve dips at 40 tasks in Figure 3a, a weak analyst gives a worse document (Table 3), and teacher traces made Trace2Skill worse (Table 5).

## What this means for Loopy

What we can no longer claim:
- That a cloud model can write a text artifact that brings a small model most of the way to the cloud model. Published here, with 75% to 95% of the gap.
- That building the artifact from the contrast between the weak and strong agent is new. Published (Table 2).
- That the small model plus artifact is cheaper per task than renting the cloud model. Published in cents (Figure 4), with a one-time build cost in dollars (Table 6).

What stays open:
- Text vs program for the same failure, same teacher, same student (C1). Not here.
- When text stops being enough as the student gets weaker (C2). Asserted in Limitation 3, never measured.
- Predicting the right remedy before paying (C3). Not here.
- Break-even that counts failed builds and rollout cost (C4). Not here.
- A per-task choice among rent, coach and compile (C5). Not here.
- Per-task harm (C6). Not here.
- A task that repeats. D-Skill tests held-out tasks only.

Tension with our pilot, and how to read it:
- D-Skill shows text can work for a weak student (28 to 72 on SSB-V). Our coach got 1 of 6. The setups differ in ways that matter. D-Skill merges 57 to 100 trace pairs into one long procedural document. Our coach note comes from one failure. D-Skill gives the analyst the teacher's full successful trace next to the student's. This is a hypothesis for why our coach is weak, not a finding.
- Our result that "procedural" failures still resisted coaching fits Limitation 3, which the authors state without data. That is a gap we can fill.

Design lessons to copy for COACH:
1. Give the cloud model both traces for the same task: the small model's failed run and the cloud model's own successful run. Paired beats student-only by about 2x in gap closed (Table 2).
2. Ask for at most 3 items. Each item: what the student did, what the expert did, ONE reusable instruction, and one concrete runtime check the student can do (Appendix B).
3. Include one "keep doing this" item so the note does not break what already works.
4. Tell the writer to compare along fixed dimensions (inspect, act, recover, verify) and to quote the trace.
5. Write rules as triggers and stop conditions with literal code idioms, as in Appendix D.
6. Use the strong model for the analysis. Merging can be cheap (Table 3).
7. Keep the cut rule for long traces: first 10,000 and last 35,000 characters.
8. Report cost the way they do (cents per task, one-time dollars), then add what they leave out: break-even and failed builds.
