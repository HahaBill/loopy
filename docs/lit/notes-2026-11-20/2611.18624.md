# Skill Transfer: Adapting Agent Skills from Strong to Weak Agents

- arXiv: 2611.18624v1, 17 Sep 2026. Lan, Wang, Lin, Chen (Penn State). Code: github.com/Yifan-Lan/Skill-Transfer
- Read on 2026-11-20 from the arXiv HTML text dump (1933 lines) and the 20-page PDF.
- Section, table and figure pointers below refer to the paper. "My reading" marks anything the paper does not state outright.

## Claim

A skill (a text file of instructions plus scripts) written for a strong model often does not help a weak model, and can hurt it. The authors say the strong model silently adds steps the skill leaves out (inspect, verify) and the weak model skips them. They fix the skill text, not the model: compare strong and weak traces on the same tasks, find where the weak procedure differs, and rewrite the skill so those steps are explicit. They call this "Skill Transfer".

Key number: across 8 weak-agent settings, the adapted skill has the best pass rate every time. It beats the original skill by 4.7 to 23.0 points and the EvoSkill baseline by up to 12.0 points (Section 4.2, Tables 3 to 5). Best case: gpt-4.1-mini on SpreadsheetBench goes 15.5 (no skill) to 25.5 (original skill) to 48.5 (adapted), which closes 55% of the gap to gpt-5.4 at 67.5.

Second number: the original skill is worse than no skill in 6 of the 8 weak settings (Section 4.2). Example: gpt-5.4-mini on SpreadsheetBench 48.0 to 39.5.

## Method (enough to reproduce)

Inputs: an original skill S0 that already works for the strong agent, about 20 training tasks, 30 validation tasks, gold answers for both (Section 3.1, 4.1). Strong and weak agent share the same harness and tools. Only the backbone differs.

1. Strong reference, once (Section 3.6, Algorithm 1 lines 1 to 2). Run the strong agent with S0 on each training task, up to M=5 tries. Keep only the tasks it solves. Those traces are the reference for the whole run.

2. Loop, K=6 iterations at most (Algorithm 1 lines 4 to 15). Each iteration:
   - Re-run the weak agent on the kept training tasks with the current skill.
   - Abstractor (an LLM) turns the strong trace and the weak trace of each task into a list of "procedure nodes", in one joint call per task so labels match (Section 3.2). Node = (tier-1 role, tier-2 tag, detail). Tier-1 is one of six fixed roles: setup, execute, validate, recover, output, other. Tier-2 is a free-text tag the LLM invents. Detail holds the completion test, tool calls, code and observations copied from the trace, and the stated reason for picking a skill (Appendix A, Listing 1).
   - Gap localization (Section 3.3). Match strong and weak nodes by label. Five gap types: missing_node (weak does a role fewer times), weak_node (role present but done to a lower bar), extra_wrong_node, order_difference, wrong_skill_routing. Every gap must quote the code or observation behind it.
   - Graph edit distance (GED) between the two node lists (Eq. 3 to 5). Substitution cost 0, 0.5, 0.75 or 1.0 by how many of the two labels match. Insert or delete costs 1. Normalized by m+n. It is a report metric only. It does not drive any decision in the loop (Section 3.3, last line of the GED paragraph).
   - Diagnoser (an LLM agent) groups per-task gaps into "systemic gaps" across the batch (Section 3.4). It also reads a validator report per task (Appendix C): the weak output compared with the strong output, not with gold. A gap is repaired if it shows in at least 1 failed task or at least 2 passed tasks.
   - Each gap gets one of six strategies (Table 1): mandate, guidance, prohibition, hard-stop, reorder, description_patch.
   - From iteration 1 on, each gap gets a status from the change in its count of failing tasks (Table 2): NEW, RESOLVED, IMPROVEMENT, PERSISTS (plain guidance is then forbidden, must escalate and replace the old instruction), REGRESSION (revert or rescope the bad edit first). Repair order: REGRESSION, PERSISTS, NEW, IMPROVEMENT.
   - The diagnoser writes a "patch hint" per gap: target file and section, strategy, wording, and a critique of the earlier patch if there was one (Appendix B, Listing 2).
   - Patcher (an LLM agent, the only one allowed to edit) applies all hints in one pass, then re-reads the skill to check for contradictions (Section 3.5).
   - Stop early if the weak agent solves every training task or the skill is unchanged twice in a row.

3. Selection (Eq. 6). The final skill is the iterate S0..SK with the best pass rate on the 30 validation tasks.

Strong-model calls. The paper gives no count and no cost. My count from Algorithm 1 for the GPT setting: 20 to 100 strong-agent task runs once, then per iteration up to 20 Abstractor calls (gpt-5.4), 1 Diagnoser agent run (gpt-5.4), 1 Patcher agent run (gpt-5.4), 20 Validator calls (gpt-5.4-mini). Over 6 iterations that is up to about 120 Abstractor calls plus 12 agent runs on the strong model.

Validation by re-running the weak agent: yes, heavily. Up to 20 training tasks x 6 iterations, plus 30 validation tasks for each candidate skill (my reading of Algorithm 1 line 12: every iteration).

Form of the transferred knowledge: text only. The patch edits SKILL.md. The diff in Appendix D (Listing 4: 4 hunks, 63 lines removed, 79 added) adds long prose rules, checklists and inline formula patterns. It adds no new script or tool. The existing recalc.py script is untouched.

## Setting, benchmarks, models

- AppWorld: not used.
- SpreadsheetBench (200 test cases, S0 = Anthropic xlsx skill). OfficeQA (70 test cases, S0 = two public skills, finance and ripgrep). DABench (150 test cases, S0 = data-scientist and statistical-analysis skills). Each has 20 and 30 further cases for training and validation (Section 4.1).
- Out of distribution: WikiTableQuestions, 250 questions, with the xlsx skill adapted on SpreadsheetBench (Section 4.5).
- GPT family: strong gpt-5.4, weak gpt-5.4-mini and gpt-4.1-mini. Abstractor, Diagnoser, Patcher on gpt-5.4. Validator on gpt-5.4-mini.
- Qwen3.5 family: strong Qwen3.5-122B-A10B-FP8, weak Qwen3.5-4B (SpreadsheetBench) and Qwen3.5-2B (DABench). All four helper roles on the 122B model. OfficeQA dropped for Qwen because documents exceed the 262,144-token context.
- Harness: tool-using loop on the OpenAI Agents SDK.
- Baselines: no skill, original skill, EvoSkill (edits the skill from the weak agent's own failures only, no strong trace).

## Metric

- Pass rate (P%): share of test tasks whose output is fully correct against gold, R(o,y)=1 (Section 3.1).
- Fine-grained: cell match ratio (SpreadsheetBench), accuracy within 0.1%, 1%, 5% relative tolerance (OfficeQA), DABench accuracy by sub-question (ByQ) and proportional by sub-question (PrQ).
- Normalized GED to the strong trace, lower is closer (Eq. 5).
- No seeds, no repeated runs, no confidence intervals anywhere.

Strong agents (no skill / original skill): gpt-5.4 SpreadsheetBench 59.0 / 67.5, OfficeQA 52.9 / 57.1, DABench 82.0 / 86.0. Qwen3.5-122B SpreadsheetBench 55.0 / 59.5, DABench 72.7 / 74.0.

Weak and negative results, most of them not stressed by the authors:
- Against no skill the gain is often small. gpt-4.1-mini OfficeQA 17.1 to 18.6 is one task out of 70. gpt-5.4-mini SpreadsheetBench +3.5. Qwen3.5-4B +4.0. Qwen3.5-2B +2.7. Much of the headline gain "over the original skill" is undoing harm the original skill caused.
- A large gap to the strong agent stays. OfficeQA 18.6 and 30.0 vs 57.1. Qwen3.5-4B 26.0 vs 59.5. Qwen3.5-2B 22.0 vs 74.0. Only DABench with gpt-5.4-mini closes fully (86.0 = 86.0), and there EvoSkill ties it.
- EvoSkill wins or ties on some columns: gpt-5.4-mini OfficeQA accuracy within 5% (40.0 vs 37.1), DABench GED (0.083 vs 0.109), DABench pass rate tie.
- EvoSkill itself is below no skill for gpt-4.1-mini OfficeQA and both Qwen settings.
- GED falls monotonically across the four methods in only 4 of 8 settings. Skill Transfer has the lowest GED in 7 of 8 (Section 4.3).
- A patch can make a gap worse. Appendix B shows a gap marked REGRESSION after the iteration-0 patch: 7 failing cases, more than before. The weak agent "satisfies the letter while skipping the real semantic check".
- Strong agent with the adapted skill: 67.5 to 76.5 (skill adapted for gpt-4.1-mini) and 81.3 (adapted for gpt-5.4-mini) on SpreadsheetBench (Table 6).
- WikiTableQuestions: gpt-4.1-mini 44.4 to 69.2, gpt-5.4-mini 75.6 to 77.6 (Table 7).

## Limitations

Authors' (Conclusion):
- Needs a strong agent and a few tasks it solves. No reference, no gap to find.
- Gain depends on why the weak agent fails. Procedural failures are "largely recoverable". Failures bound by missing capability are "difficult to recover from". They do not measure which is which.

Mine:
- No cost numbers at all. No tokens, dollars, calls or time. The build is heavy (my count above) and the adapted skill is much longer, so each weak run also costs more. None of this is reported.
- Single run per cell. No seeds, no intervals. On OfficeQA one task is 1.4 points, so several gaps are one or two tasks.
- No ablation. We do not know whether the typed abstraction, the GED, the status logic or the strong trace matters. The EvoSkill comparison mixes all of them.
- GED is computed on labels an LLM invents. No check of label reliability. GED is not used by the method, only reported.
- Needs gold answers on training and validation tasks.
- The validator scores the weak output against the strong output, not gold. If the strong output is wrong in some detail, the patch teaches that.
- The adapted skill in Appendix D holds very task-specific rules (latest-N-nonblank formulas, date series, category codes with numeric suffixes). That looks like fitting to the 20 training tasks. The WikiTableQuestions test supports transfer for one skill only.
- Small inconsistencies. Table 6 reports 81.3% on a 200-case split, which is not a possible value at 0.5-point steps. Cell match is a fraction in Table 3 and a percent in Table 4. For gpt-5.4 on OfficeQA with no skill, pass rate (52.9) is below accuracy within 0.1% (57.1), so "pass" must use a different rule that the paper does not define.
- One skill per benchmark. No per-task analysis of who was helped or hurt.

## Assumptions not tested

- That the strong agent's extra steps are what make it succeed. Tested only through the outcome, never by adding steps one at a time.
- That lower GED causes higher pass rate. Correlation in 4 to 7 of 8 settings.
- That text is a sufficient channel for the weak agent. Never compared with giving the weak agent a script or tool that does the step.
- That failures split cleanly into "procedural" and "capability". Stated in the Conclusion, not measured.
- That a skill tuned on 20 tasks generalizes within the benchmark. Tested by held-out pass rate only, one run.

## C1 to C7

- C1 forms (text vs program): NOT. Text edits to SKILL.md only (Section 3.5, Appendix D). No executable arm.
- C2 student strength: PARTLY. Four weak students (table above, Tables 3 to 5). No analysis of when advice is enough. The pattern is visible but not discussed: the weakest pairs (Qwen3.5-2B, Qwen3.5-4B, gpt-4.1-mini on OfficeQA) gain almost nothing over no skill.
- C3 predict before paying: NOT. The gap type picks the wording of the patch (Table 1). Nothing predicts whether a patch will work. They find out by re-running the weak agent.
- C4 economics: NOT. No cost unit, no build cost, no break-even. Failed patches exist (REGRESSION, PERSISTS) but are not priced.
- C5 online choice or routing: NOT. One skill per benchmark, fixed offline. Only "wrong_skill_routing" among skills, fixed by editing the skill description.
- C6 harm: PARTLY. Original skill below no skill in 6 of 8 (Section 4.2). EvoSkill below no skill in 3 of 8 (Tables 3 to 5). A patch that increases failures (Appendix B). No per-task harm analysis, no harm rate for their own final skill.
- C7 execution gap: PARTLY. Closest idea is the weak_node gap: step present but done to a lower bar (Section 3.3), and the Appendix B case where the weak agent follows the letter of the patched instruction and skips the real check. Measured only as GED and as failing-case counts per gap. Fix: stronger text (mandate, hard-stop, checklists, replace rather than append). The leftover gap after the fix is large and unexplained.

## What this means for Loopy

What we can no longer claim:
- That building advice from where the weak agent's trace departs from the strong agent's is new. This paper does it with typed nodes and gap types (and D-Skill, 2610.28914, does a version too).
- That "a skill can hurt a weak agent" is our finding. 6 of 8 here.
- That a one-shot note is a fair picture of what text can do. Their text arm gets 6 rounds of re-run and repair, with escalation.

Design lessons to copy:
- Give COACH an honest chance. One note, written once, is weaker than their loop. Add a "coach with re-run and repair" arm (a few rounds, select on held-out repeats). Otherwise a reviewer will say compile only beat a strawman.
- Track each failure cause across rounds with a status (persists, regressed, resolved). "Persists after an explicit instruction" is a clean, cheap signal that text is not the right form for this failure. That is a candidate trace feature for our predictor.
- Use their gap types as trace features: missing step vs step present but weak vs extra wrong step. Our pilot note failures look like weak_node or persists cases.
- Report the no-help baseline next to every arm and count harm per task.
- Their escalation ladder stops at "hard-stop" text. The next rung is a program that does the step. That rung is our COMPILE arm.

What stays open after this paper:
- Text vs program for the same failure, teacher and student. Not touched.
- Why 20 to 50 points of gap remain after six rounds of text repair. A compile arm on those leftover failures is the direct test.
- Any cost accounting, break-even over repeats, prediction before paying, per-task routing, AppWorld or API tasks.
- Risk: this group also wrote SkillGrad and has code out. Adding scripts to the patch is an easy next step for them.
